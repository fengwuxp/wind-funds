# OpenSpec Project Context

## 一、定位

`openspec/` 是支付资金底座的生产交付规格入口，用于把 `docs/` 下的产品、DSL、系分和 TDD 设计压缩成可评审、可实现、可验证的稳定边界。

本目录不保存过程计划、历史状态、临时评审结论或历史演进材料。任何工程变更都必须回到当前设计文档、当前源码、当前测试和 Git 提交点取证。

## 二、权威入口

| 层级 | 权威入口 | 用途 |
| --- | --- | --- |
| 产品设计 | `docs/产品设计/README.md` | 判断业务目标、角色、对象、能力边界、非目标和验收口径。 |
| DSL 设计 | `docs/DSL设计/支付资金底座DSL承载层设计.md` | 判断资金事实、指令、路由快照、账务计划、分录、投影和 JSON 契约。 |
| 系分设计 | `docs/系分设计/README.md` | 判断模块边界、服务契约、状态机、表设计、事务、观测和安全边界。 |
| TDD 设计 | `docs/TDD设计/支付资金底座测试驱动设计.md` | 判断测试分层、场景矩阵、红线用例、资金断言和验证命令。 |
| OpenSpec | `openspec/specs/payment-funds-foundation/spec.md` | 汇总生产交付规格和跨文档裁决。 |
| 测试资源 | `tests/src/test/resources/jdbc-schema.sql` | H2/MySQL Mode 测试表结构来源。 |

导出包、归档材料、历史计划和未提交草稿只能作为背景输入，不能替代上述权威入口。

## 三、生产交付基线

支付资金底座的交付目标是：

> 每一笔资金事实都能被解释、被核对、被重建，并能通过测试证明状态、主体、账目、route、posting、ledger entry、余额投影、幂等和失败无副作用成立。

稳定优先级如下：

| 顺序 | 能力域 | 交付口径 |
| --- | --- | --- |
| 1 | 账本、账目、余额投影 | 先保证账本事实、分录平衡、余额桶、账本周期和只读投影可追溯。 |
| 2 | 钱包账户和支出控制 | 再保证资金账户、信用账户、平台账户角色、预算控制范围和 Spend Rule 控制事实边界清楚。 |
| 3 | 交易层 | 在账本和钱包语义稳定后承接直接交易、授权交易、余额控制、让利出资记账、路由回放和交易投影。 |
| 4 | 清结算、对账和治理 | 作为运营账务闭环和事实治理能力交付，只通过 face/core 消费交易与账本事实。 |
| 5 | 支付工具、VCC、全球账户、外部轨道 | 作为业务能力包接入资金底座，不新增平行资金内核。 |
| 6 | 收单能力 | 当前只保留产品和系统设计，不进入默认实现范围。 |

## 四、工程变更准入

设计文档齐备不等于可以直接修改代码。任何代码、测试、表结构、运行配置或公共契约变更，必须先能回答：

| 检查项 | 必须明确 |
| --- | --- |
| 交付范围 | 服务哪个使用者，处理哪类资金事实，证明哪条最小可验证闭环。 |
| 权威依据 | 产品验收、DSL case、系分章节、TDD 用例、当前 Git 基线和允许参考的未提交变更。 |
| 写入范围 | 可改模块、包、公共契约、枚举、Request/Query/DTO、状态机、表结构、H2 schema 和测试资源。 |
| 禁止范围 | 不触碰的模块、业务能力、资金语义、外部协议、敏感数据和生产完成声明。 |
| 资金不变量 | 主体、账户类型、账目、币种、route、posting、entry、projection、幂等、审计和失败无副作用。 |
| 验证方式 | 编译、专项测试、边界测试、规约扫描或无法执行的环境原因。 |
| 外部确认 | 涉及法务、合规、税务、会计、通道、卡组织、银行、FX 或敏感数据时的确认状态和不覆盖范围。 |

## 五、交付判定

交付结论必须基于实现证据，而不是设计完整度。生产交付必须同时具备：

1. 代码和公共契约只在明确写入范围内变更。
2. DSL、系分、请求模型、状态机、表结构和测试断言语义一致。
3. 有资金变化的测试同时断言状态、route snapshot、posting plan、ledger entry、余额投影、幂等和失败无副作用。
4. 涉及持久化时，生产 DDL、H2 schema、Entity、Mapper、唯一键和索引同步闭合。
5. 涉及生产行为时，并发、锁、容量、观测、告警、回滚、补偿和人工处理边界清楚。
6. 涉及真实资金、外部规则或敏感数据时，确认状态、证据引用和脱敏边界清楚。
7. 交付说明列出修改模块、覆盖测试清单、验证命令、验证结果、未覆盖范围和残余风险。

不满足上述条件时，只能声明为设计输入、差距复核、局部验证或受限交付，不能声明对应能力生产可用。

## 六、语言规则

OpenSpec 和设计文档默认使用简体中文。代码标识符、协议字段、枚举、命令、包名、类名和第三方产品名保持英文原文。
