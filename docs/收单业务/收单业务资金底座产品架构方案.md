# 收单业务资金底座产品架构方案

## 1. 一页结论

收单业务不应整体放进 `wind-funds`。`wind-funds` 的产品定位是支付资金底座，应承接收单业务产生后的资金事实、账户余额、账本分录、清结算、对账、结算出款、争议资金影响、投影、归档和重放；不直接承接商户入网、收银台、支付网关、通道报文、卡数据合规、商户风控策略和完整收单经营后台。

这份设计适用于业务模式尚未确定时的产品架构预案。它回答两个问题：

1. 如果未来有收单业务，`wind-funds` 应支持哪些资金底座能力。
2. 哪些能力必须留在外部收单产品、支付网关、商户系统、风控合规系统或通道系统中。

## 2. 设计目标

### 2.1 业务目标、用户价值、成功指标和非目标

业务目标是让未来收单业务在不确定业务模式下，仍能把商户待结算资金、平台手续费、通道成本、退款拒付、风险预留、结算出款和对账差错纳入统一资金底座解释。

用户价值是让商户、运营、财务、风控和审计都能回答同一个问题：一笔收单资金当前处在哪个资金状态，为什么可结算或不可结算，后续退款、拒付、出款失败或对账差异应如何处理。

成功指标是任一收单资金事件都能追溯到业务引用、外部收单事件、资金指令、route snapshot、posting plan、账本分录、清结算批次、对账结果和只读投影。

非目标是不在业务模式未确认前设计完整收单经营系统，不把商户入网、收银台、支付网关、卡组织协议、PCI Token Vault、风控模型或合规结论放进 `wind-funds` 默认职责。

| 目标 | 说明 | 验收口径 |
| --- | --- | --- |
| 明确项目边界 | 收单经营能力和资金底座能力分离。 | 评审时能判断一个需求属于 `wind-funds`、外部收单产品还是待确认。 |
| 承接资金事实 | 外部收单事件进入资金底座后可落到账户、路由、账本和投影。 | 每笔金额可追溯到资金事实、route snapshot、posting plan 和 ledger entry。 |
| 支撑商户资金视图 | 商户可理解待清算、可结算、结算锁定、出款中、已出款、预留和追偿。 | 商户账单和运营时间线能解释金额状态和不可操作原因。 |
| 支撑清结算与对账 | 外部收单流水、通道文件、银行流水、内部账本和结算单可核对。 | 对账差异进入差错、阻断、调账、核销和重新对账闭环。 |
| 保留未来扩展 | 不因当前业务不确定而提前把卡组织协议、PSP 协议或 PCI 数据模型写入核心。 | DSL 只保留中立引用和资金语义，外部规则用待确认项表达。 |

## 3. 能力边界

### 3.1 放在 wind-funds 的能力

| 能力 | 产品解释 |
| --- | --- |
| 收单资金事实承接 | 接收外部收单系统确认后的支付、授权完成、退款、拒付、清分、结算和出款结果。 |
| 商户资金账户 | 承载商户待清算、可结算、结算锁定、出款中、风险预留、负余额和追偿口径。 |
| 资金路由与账务计划 | 把用户实付、商户应收、平台手续费、通道成本、补贴、预留和扣减项拆成可入账路径。 |
| 账本事实和余额投影 | 通过不可变分录解释每一次余额变化，并支持余额重建。 |
| 清分、清算、结算、出款 | 按商户、币种、账期、规则版本和风险状态生成清分结果、清算批次、结算单和出款单。 |
| 对账与差错 | 核对内部交易、账本、通道流水、清分文件、银行流水、结算单和出款回单。 |
| 逆向资金影响 | 承接退款、撤销、冲正、拒付、争议、追偿和负余额治理的资金影响。 |
| 交易投影和归档重放 | 为商户、运营、财务、审计提供只读视图，并支持归档后重放和差异报告。 |

### 3.2 不默认放在 wind-funds 的能力

| 能力 | 推荐归属 | 原因 |
| --- | --- | --- |
| 商户入网、KYB、MCC、合同、费率协议 | 商户系统、风控合规系统 | 属于商户经营与资质管理，不是资金底座核心事实。 |
| 收银台、SDK、支付页面、支付方式展示 | 支付接入产品 | 属于用户支付体验和接入产品。 |
| PSP、银行、卡组织报文适配 | 支付网关或通道系统 | 涉及签名、加密、协议转换、重试、通道 SLA 和外部认证。 |
| PAN、CVV、原始卡数据、Token Vault | 专用 PCI 边界系统 | 资金底座只保存 token、reference、脱敏摘要和审计引用。 |
| 欺诈风控模型和商户风险策略 | 风控系统 | 资金底座消费风控结论、阻断原因和规则版本，不承载模型决策。 |
| 法务、合规、会计最终结论 | 专业确认方 | 资金设计只能记录确认状态和待确认项，不能替代专业结论。 |

## 4. 参与方和主体

| 角色 | 关注点 | 在 wind-funds 中的表达 |
| --- | --- | --- |
| 付款人 / 持卡人 | 是否支付成功、是否退款、是否被重复扣款。 | 只在交易投影和资金来源引用中表达，不直接作为外部卡数据主体。 |
| 商户 | 哪些订单款待清算、可结算、被扣费、被预留或被追偿。 | 商户资金账户、商户账单、清结算批次、结算单和出款单。 |
| 平台 | 手续费收入、通道成本、补贴、差错、风险预留和追偿。 | 平台账户角色、费用 leg、差错单、调账事实和报表输入。 |
| 外部收单产品 | 支付订单、支付尝试、授权、扣款、退款和回调处理。 | 作为上游事实来源，向 `wind-funds` 提供中立事件和引用。 |
| 支付网关 / 通道 | PSP、收单行、卡组织、银行接口。 | 作为外部引用、对账来源和出款/到账回单来源。 |
| 风控合规 | 商户风险、交易风险、名单筛查、结算阻断。 | 风控结论、规则版本、阻断原因和外部规则核验状态。 |
| 财务 / 审计 | 账务是否平、结算净额是否可解释、差错是否闭环。 | 账本分录、对账批次、差错单、审计证据和导出。 |

## 5. 四流建模

| 四流 | 收单业务中的对象 | wind-funds 承接边界 |
| --- | --- | --- |
| 业务流 | 订单、履约、售后、商户结算诉求、争议工单。 | 只引用业务事实，不判断订单是否成立或履约是否完成。 |
| 支付信息流 | 支付订单、支付尝试、授权、扣款、退款、通道通知、补单。 | 接收外部确认结果和引用，不实现通道协议。 |
| 账户 / 账务流 | 商户待清算、可结算、结算锁定、出款中、平台费用、预留、追偿。 | 通过资金账户、route snapshot、posting plan、ledger entry 和余额投影承接。 |
| 真实资金流 | 付款人资金、通道或清算机构处理、平台收款账户、商户出款银行。 | 以外部流水、银行流水、通道文件和回单作为对账来源，不直接承诺外部资金已到账。 |

## 6. 产品能力地图

| 能力域 | 核心能力 | 非目标 |
| --- | --- | --- |
| 收单事件承接 | 收单事件准入、幂等、外部引用、事实摘要、乱序处理。 | 不做支付页面和通道报文。 |
| 交易与路由 | 资金指令、资金交易、费用拆分、route snapshot、原路径回放。 | 不按当前商户配置重算历史交易。 |
| 钱包与账户 | 商户账户、平台账户、待清算、可结算、结算锁定、在途和预留。 | 不把商户经营主体、卡、VA、外部账户直接入账。 |
| 账本与投影 | 账本交易、分录、余额投影、商户账单、运营时间线。 | 投影不得反写交易或账本事实。 |
| 清结算 | 清分、清算、结算单、出款单、追偿、风险预留。 | 不表达持牌清算业务，不替代税务会计规则。 |
| 对账差错 | 交易对账、通道对账、资金到账对账、结算对账、差错核销。 | 对账通过不写账，差异不直接改历史分录。 |
| 逆向与争议 | 退款、撤销、冲正、拒付、争议费、负余额、追偿。 | 拒付不压缩成普通退款，争议证据不保存敏感原文。 |
| 归档重放 | 事实归档、交易投影重放、余额重建、差异报告。 | 报表数仓不得反写资金事实。 |

## 8. 状态和红线

### 8.1 业务流程、主流程、异常流程和人工兜底

主流程是外部收单产品确认支付或扣款结果后，向 `wind-funds` 发送中立收单事件；资金底座完成幂等校验、资金交易创建、路由解析、账本过账、余额投影和商户交易投影；后续由清结算能力识别可清分明细、生成清算候选、确认清算批次、生成结算单并按门禁提交出款。

异常流程包括外部事件重复、乱序、金额不一致、缺原交易、通道文件晚到、退款和拒付碰撞、风控阻断、对账重大差错、出款受理后失败、银行回单金额不一致和敏感证据缺失。

人工兜底只能处理排除、恢复、复核、补证据、挂账、审批调账、追偿和重新对账，不能直接修改原交易、历史分录、余额投影或交易投影。

状态机口径必须拆分支付信息状态、资金事实状态、清结算状态、出款状态和差错状态；任何视图都不得用一个“成功”覆盖授权、扣款、清算、结算、出款和到账。

| 场景 | 正确表达 | 必须避免 |
| --- | --- | --- |
| 授权成功 | 支付信息流成功或授权占用成立。 | 展示为商户已收款或可结算。 |
| Capture / 扣款成功 | 外部收单事件可进入资金事实。 | 直接展示为银行到账。 |
| 清分完成 | 已归类并可复核。 | 触发 `CLEARING -> AVAILABLE`。 |
| 清算确认 | 符合规则后从待清算进入可结算。 | 跳过前置对账和阻断规则。 |
| 结算锁定 | 可结算金额被锁定用于出款。 | 展示为出款成功。 |
| 外部受理 | 出款请求已提交或处理中。 | 展示为商户银行到账。 |
| 拒付 | 争议、扣回或追偿路径。 | 压缩成普通退款。 |
| 对账差异 | 差错单、挂账、调账、核销。 | 直接修改历史分录或余额。 |

### 8.2 规则矩阵

| 规则 | 触发条件 | 判断逻辑 | 优先级 | 版本和审计 |
| --- | --- | --- | --- | --- |
| 收单事件准入 | 收到外部支付、扣款、退款、拒付或出款结果。 | 校验幂等键、外部引用、金额币种、主体、脱敏摘要和事件状态。 | P0 | 记录事件来源、摘要、接收时间和处理结果。 |
| 敏感数据过滤 | 输入包含卡、账户、通道或证据引用。 | PAN、CVV、密钥、完整原文不得进入资金快照、日志、归档或导出。 | P0 | 记录脱敏策略、digest 和证据引用。 |
| 清算前置对账 | 清分结果准备进入清算候选。 | 重大差错、风控阻断、退款争议未闭环时不得放行。 | P0 | 记录规则版本、确认方和阻断原因。 |
| 结算出款门禁 | 结算单准备提交出款。 | 出款账户、收款端点、cutoff、名单、外部规则、负余额、准备金、审批任一未知或失败则阻断。 | P0 | 记录门禁明细、审批号和外部规则核验状态。 |
| 逆向原路径回放 | 退款、撤销、退费、拒付或追偿。 | 必须引用原 route snapshot、原支付工具快照和原费用 leg；缺失时失败或转人工。 | P0 | 记录原始引用、回放摘要和人工处理入口。 |
| 对账差错处理 | 内部事实与外部文件或银行流水不一致。 | 差异进入差错单，审批后追加补事实、冲正、调账或追偿。 | P0 | 记录差错等级、责任方、凭证、核销和重新对账结果。 |

## 9. 账务和金额口径

收单资金底座必须拆分以下金额，不能只保留净额：

| 金额项 | 说明 |
| --- | --- |
| grossAmount | 交易总额或订单应付金额。 |
| payerPaidAmount | 付款人实际支付金额。 |
| merchantReceivableAmount | 商户应收金额。 |
| platformFeeAmount | 平台手续费或服务费。 |
| channelCostAmount | 通道成本、网络费用、处理费等。 |
| benefitAmount | 平台补贴、商户让利、代金券、储值权益等。 |
| reserveAmount | 风险预留、rolling reserve 或 delayed settlement。 |
| refundAmount | 退款金额。 |
| chargebackAmount | 拒付、争议扣回或追偿金额。 |
| settlementAmount | 结算单净额。 |
| payoutAmount | 实际出款金额。 |

## 10. 验收矩阵

| 验收项 | 必须证明 |
| --- | --- |
| ACQ-PRD-001 | 收单经营能力和资金底座能力边界清楚。 |
| ACQ-PRD-002 | 支付成功、授权、扣款、清算、结算、出款、到账状态不混用。 |
| ACQ-PRD-003 | 商户资金状态可解释，待清算、可结算、出款中、已出款、预留和追偿可区分。 |
| ACQ-PRD-004 | 退款、撤销、冲正、拒付和追偿具备不同资金语义。 |
| ACQ-PRD-005 | 对账差异不会直接改账，必须进入差错和审计闭环。 |
| ACQ-PRD-006 | 敏感卡数据、通道密钥、原始报文不进入资金快照、日志、归档或导出。 |
| ACQ-PRD-007 | 外部规则、法域、资质、资金归属和财税口径未确认时只能作为待确认项。 |

## 11. 分期计划

## 12. 待确认项

| 待确认项 | 影响 |
| --- | --- |
| 平台角色是普通平台、支付机构、PSP、聚合收单方还是被赞助商户服务商。 | 决定资质、资金归属、合规义务和外部规则适用范围。 |
| 收单轨道是卡、ACH、钱包、本地支付方式还是多轨道。 | 决定授权、清算、争议、费用和对账文件模型。 |
| 是否由本仓库承接支付订单和支付尝试生命周期。 | 决定是否需要新增独立收单应用层模块。 |
| 是否涉及跨境、多币种、外汇或客户备付金。 | 决定专业确认和资金红线。 |
| 商户风险预留、负余额、追偿和结算暂停规则。 | 决定商户资金账户、清结算和运营后台设计。 |
