# wind-funds 用户接入宣讲提纲

## 1. 文档定位

本文用于产品、研发、测试、运营、财务、风控、安全和合规团队的接入宣讲。目标是让听众在一次会议内理解 wind-funds 的定位、接入边界、标准流程、评审材料和阻断红线。

本文不是 PRD、DSL、系分、TDD 或 API 手册。宣讲只能帮助团队形成共同语言，不能替代接入评审、Execution Grant、测试验证、外部规则确认或上线审批。

## 2. 业务目标和非目标

| 项 | 说明 |
| --- | --- |
| 业务目标 | 用一场宣讲让产品、研发、测试和运营团队理解如何把上层业务资金动作接入 wind-funds。 |
| 用户价值 | 降低首次接入沟通成本，减少概念混用、流程断点和资金安全误用。 |
| 非目标 | 不讲具体代码实现，不承诺生产上线，不现场决定公共契约、表结构或外部规则。 |
| 成功指标 | 会后团队能使用资金事实说明卡、接入申请、接入评审清单和样例完成首轮接入准备。 |

## 3. 30 分钟宣讲版本

| 时间 | 主题 | 重点 | 参考材料 |
| --- | --- | --- | --- |
| 0-5 分钟 | wind-funds 定位 | 资金底座，不是 VCC、ACH、收单、通道网关、风控、KYC/KYB、报表或会计总账。 | 用户接入指南 1-2 |
| 5-10 分钟 | 接入前先问什么 | 谁的钱、什么业务事实、哪个主体、金额币种、幂等、外部规则、DSL 借贷表命中行、怎么验收。 | 资金事实说明卡模板 |
| 10-15 分钟 | 标准接入流程 | Round 0、账户和工具准备、资金交易、投影解释、接入交付包、Execution Grant。 | 用户接入指南 6 |
| 15-20 分钟 | 样例讲解 | 商户订单收款、提现前冻结后确认出款。 | 接入样例 |
| 20-25 分钟 | 常见误用和阻断 | 支付工具当账户、冻结当扣款、授权当消费、外部 pending 当成功、差错直接改账。 | FAQ 与误用排查 |
| 25-30 分钟 | 下一步 | 填卡、提交申请、评审会、Execution Grant、TDD 和编码准入。 | 接入评审清单 |

## 4. 60 分钟工作坊版本

| 时间 | 主题 | 工作方式 | 输出 |
| --- | --- | --- | --- |
| 0-10 分钟 | 定位和能力地图 | 讲解 P0/P1/P2、四流和职责边界。 | 共同语言。 |
| 10-20 分钟 | 样例拆解 | 用商户订单收款样例拆主体、账户类型、`normalBalanceSide`、金额、route、posting、entry、projection 和余额影响。 | 样例验收证据链。 |
| 20-30 分钟 | 模板填写演示 | 现场按一个候选业务填写资金事实说明卡。 | 候选资金事实说明卡草稿。 |
| 30-40 分钟 | 误用排查 | 对照 FAQ 检查支付工具、冻结、授权、清结算、外部非终态和对账差错。 | 阻断项和待确认项。 |
| 40-50 分钟 | 接入申请和评审清单 | 补能力成熟度、公共契约影响、表结构影响、TDD 和验证命令。 | 接入申请草稿。 |
| 50-60 分钟 | 结论判定 | 判断通过、带条件通过、阻断或仅 TDD 分析。 | 负责人、补齐时间和下一步。 |

## 5. 宣讲能力地图

| 能力域 | 听众要理解的点 | 宣讲材料 | 验收问题 |
| --- | --- | --- | --- |
| 钱包账户和资金账户 | FundingAccount 是资金载体，不是支付工具或外部账户。 | 用户接入指南 3、5 | 业务对象能否映射可记账主体。 |
| 支付工具和资金来源 | 卡、VA、银行账户、token 只做引用和 route 输入。 | 用户接入指南 2.3、5 | 是否保存敏感原文或把外部账户入账。 |
| 直接交易 | 已成立资金事实进入交易编排。 | 用户接入指南 7.1、接入样例 | 是否证明 route、posting、entry 和投影。 |
| 授权交易 | 授权是占用，不是最终消费。 | 用户接入指南 7.2 | 拒绝是否无资金副作用。 |
| 余额控制 | 冻结是同主体余额桶控制，不是扣款。 | 用户接入指南 7.3 | 冻结后扣划是否形成独立资金事实。 |
| 对账清结算 | 差错、清算、结算、出款都是专项准入。 | 用户接入指南 7.4 | 是否把外部非终态展示成功。 |
| 归档重放 | 重放只重建投影或输出差异。 | 用户接入指南 7.5 | 是否用重放生成资金事实。 |
| P2 业务能力包 | VCC、全球账户、ACH、收单只归一资金事实接入。 | 用户接入指南 7.6、FAQ | 是否把外部协议沉入资金内核。 |

## 5.1 核心决策、接口契约和验证方案

| 维度 | 宣讲口径 | 不展开的内容 |
| --- | --- | --- |
| 核心决策 | 业务接入优先走 `core`、`*-face` 和授权公共契约；P2 业务能力包只归一资金事实，不改统一资金内核。 | 不现场决定新增 Request、DTO、枚举、状态机或表结构。 |
| 职责边界 | wind-funds 承接资金事实、账户、路由、账务、投影、对账清结算和治理边界。 | 不承接外部协议全集、业务审批、风控模型、KYC/KYB 或合规最终判断。 |
| 接口契约 | 入参要有业务流水、幂等键、请求摘要、主体、金额、币种、来源引用和操作者；出参要能解释状态、失败原因和审计引用。 | 不讲具体 Java 字段冻结口径，真实契约由 Execution Grant 确认。 |
| 错误码 | 失败要区分准入失败、幂等冲突、路由失败、账务失败、投影失败、外部非终态和对账差错。 | 不把错误码设计成宣讲现场结论。 |
| 数据方案 | 余额事实源来自 ledger entry，投影只读可重建，报表只消费事实和投影。 | 不把报表、日志或运营备注当余额事实源。 |
| 借贷平衡 | 资金变化必须回挂 DSL 资金场景借贷平衡与账务期望表，说明命中行、不适用行、账户类型、`normalBalanceSide`、借贷平衡和余额影响。 | 不在宣讲现场按付款方和收款方口头推导借贷方向。 |
| 事务边界和一致性 | route、posting、ledger entry、projection、幂等和审计必须能说明一致性边界。 | 不用“最终一致”掩盖无补偿、无对账、无告警。 |
| 补偿和对账 | 差错通过补事实、冲正、调账、追偿、核销和重新对账闭环。 | 不允许后台直接改历史分录。 |
| 验证方案 | 测试要覆盖状态、金额、route、posting、entry、projection、幂等、审计、失败无副作用和回归范围。 | 不用接口联调成功替代资金验收。 |

## 6. 对象、状态和规则讲解顺序

| 顺序 | 讲什么 | 为什么先讲 |
| --- | --- | --- |
| 1 | 业务事实 | 没有已成立资金事实，就不应进入资金底座。 |
| 2 | 主体和资金归属 | 不知道谁的钱，就无法安全记账。 |
| 3 | 支付工具和外部引用 | 避免把外部账户、卡、token 当账本主体。 |
| 4 | route snapshot | 解释退款、撤销、拒付和后续事件为什么不能重新选路。 |
| 5 | DSL 借贷表和 normalBalanceSide | 说明借贷方向不是付款方和收款方的口头翻译，余额影响来自账户类型和 `normalBalanceSide`。 |
| 6 | posting plan 和 ledger entry | 说明余额事实源来自账本，不来自接口返回或报表。 |
| 7 | projection | 说明用户账单、商户账单和运营时间线都是只读派生。 |
| 8 | 对账、清结算和归档 | 说明运营闭环和治理能力需要专项准入。 |

## 6.1 业务流程、主流程和异常流程

| 流程 | 宣讲讲法 | 需要听众确认 |
| --- | --- | --- |
| 业务流程 | 上层业务先形成确定资金事实，再提交接入材料。 | 页面动作、审批中、通道处理中和外部非终态不进入资金底座。 |
| 主流程 | 资金事实通过准入检查，生成 route、posting、ledger entry，再派生 projection 和审计。 | 接入方不能只关心接口返回成功。 |
| 异常流程 | 准入失败、幂等冲突、路由失败、账务失败、投影失败、外部非终态和对账差错分别处理。 | 每类失败都要有停止条件和验收证据。 |
| 人工兜底 | 缺原 route snapshot、缺原冻结单、外部规则待确认、对账差错或出款状态不明时转人工补证据或阻断。 | 人工处理也要有审批、凭证、审计和重新对账。 |
| 状态机 | 业务状态、交易状态、展示状态、操作状态和外部状态不得混用。 | 授权、冻结、清算、结算和出款不能都叫成功。 |

## 7. 宣讲规则矩阵

| 规则对象 | 讲法 | 听众必须记住 |
| --- | --- | --- |
| 幂等 | 重试可以发生，但不能重复入账。 | 同键同摘要复用，同键不同摘要失败。 |
| 主体 | 支付工具不是账户，外部账户不是 ledger subject。 | 先解析可记账主体。 |
| 金额 | 金额组件必须闭合。 | 手续费、补贴、税费和权益不能糊成净额。 |
| 路由 | 后续事件优先引用原 route snapshot。 | 换绑工具后不能默认按当前绑定退款。 |
| 账务 | 账本是余额事实源，借贷口径回挂 DSL 权威表。 | 不直接改余额、投影或历史分录，不按付款方/收款方口头推导借贷方向。 |
| 运营 | 差错处理必须有单据、审批、凭证和重新对账。 | 后台不是通用改账入口。 |
| 外部规则 | 未确认规则不驱动自动资金处理。 | 待确认要写确认方、范围和未确认期间处理方式。 |

## 8. 现场演练题

| 题目 | 期望结论 |
| --- | --- |
| 用户点击提现按钮，审批还没通过，能否进入 wind-funds。 | 不能；审批中不是已成立资金事实。 |
| PSP 返回 payment accepted，能否展示商户已到账。 | 不能；外部 accepted 不是终态成功。 |
| 授权拒绝后是否生成 ledger entry。 | 不生成；只保留审计和拒绝原因。 |
| 冻结后确认出款，是否直接把冻结改成扣款。 | 不建议；出款确认形成独立资金事实并引用原冻结单。 |
| 对账差错发现少记一笔，是否直接补分录。 | 不能；走差错单、审批、补事实或冲正、重新对账。 |
| ACH return code 是否由 wind-funds 解析。 | 不解析；由上层业务或适配层归一成资金事实。 |

## 9. 宣讲后的行动项

| 行动项 | 负责人 | 输出 |
| --- | --- | --- |
| 选择首个接入场景 | 产品、业务 | 业务目标、非目标和能力成熟度。 |
| 填资金事实说明卡 | 业务、产品、研发 | 资金事实、主体、金额、路由、账务影响和失败处理。 |
| 填接入申请 | 业务、产品、研发、测试 | 公共契约影响、表结构影响、外部规则、验证命令和生产准入补充。 |
| 组织接入评审 | 产品、架构 | 通过、带条件通过或阻断结论。 |
| 准备 Execution Grant | 架构、研发、测试 | 写入范围、只读范围、TDD、验证命令和停止条件。 |

## 9.1 宣讲到评审的交接清单

宣讲结束后，如果团队准备进入接入评审，应先完成下列交接。交接不完整时，可以继续补材料或做 Round 0 讨论，不应直接进入编码任务拆解。

| 交接项 | 最小要求 | 不完整时的处理 |
| --- | --- | --- |
| 候选接入场景 | 能说清业务目标、非目标、触发条件、使用者和期望结果。 | 回到产品澄清，不进入资金事实拆解。 |
| 资金事实说明卡 | 每个资金动作都有主体、资金归属、金额、币种、幂等、route、账务影响、DSL 借贷表命中行、不适用行和失败处理。 | 回到业务和产品补卡。 |
| 概念映射 | 业务对象已经映射到 FundingAccount、CreditAccount、BudgetGroup、PaymentInstrument、RouteSnapshot、LedgerEntry、Projection 或只读引用。 | 回到账户建模、支付工具绑定或业务对象澄清。 |
| 外部规则和敏感数据 | 已说明规则来源、版本或发布日期、生效日期、适用范围、核验日期、确认方、确认状态和脱敏边界。 | 未确认期间不得驱动自动资金处理。 |
| 验收证据草案 | 已列 PRD AC/RED、DSL caseId、系分章节、TDD 用例、目标测试资产和验证命令。 | 只能进入 TDD 分析或设计补齐。 |
| 评审组织信息 | 已明确参会角色、材料负责人、评审范围、非目标和期望结论。 | 不能形成正式接入结论。 |

## 10. 宣讲边界和风险提示

宣讲通过不代表生产 Done。任何接入都必须继续证明：公共契约、实现、DDL/H2、测试资源、验证命令、权限审计、外部规则、灰度、回滚和 Runbook 已按 Execution Grant 闭合。
