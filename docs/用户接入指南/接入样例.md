# wind-funds 接入样例

## 1. 文档定位

本文给接入方一个可照着填写的样例视图，帮助产品、研发、测试、运营、财务、风控和安全评审方理解：资金事实说明卡应该填到什么粒度，伪请求应该表达哪些字段，验收矩阵应该证明哪些资金不变量。

本文不是 API 契约，也不是生产上线说明。真实 Request、DTO、错误码、表结构、H2 schema、测试类和验证命令必须在具体 Execution Grant 中确认。

## 1.0 业务目标和流程边界

| 项 | 样例口径 |
| --- | --- |
| 业务目标 | 用两个常见接入场景说明上层业务如何把已成立资金动作归一为 wind-funds 可接收的资金事实。 |
| 用户价值 | 产品、研发、测试、运营、财务、风控和安全可以用同一份样例判断怎么填卡、怎么映射概念、怎么设计验收。 |
| 非目标 | 不定义真实 API 字段，不替代 PRD、DSL、系分、TDD、Execution Grant、合规确认或上线审批。 |
| 业务流程 | 业务确认资金事实 -> 填资金事实说明卡 -> 做 Round 0 准入 -> 准备账户和工具 -> 提交伪请求和验收矩阵 -> 进入 Execution Grant。 |
| 主流程 | 主体、账户类型、`normalBalanceSide`、金额、币种、幂等、route、posting、ledger entry、projection、借贷平衡、余额影响和审计均闭合后，进入小批次接入验证。 |
| 异常流程 | 准入失败、幂等冲突、路由失败、账务失败、投影失败、外部非终态和对账差错都必须无错误资金副作用。 |
| 人工兜底 | 外部规则未确认、缺原 route snapshot、缺原冻结单、对账差错或出款状态不明时，转人工补证据或阻断。 |

## 1.1 样例能力地图

| 能力域 | 前台能力 | 后台能力 | 数据能力 | 风险边界 |
| --- | --- | --- | --- | --- |
| 商户订单收款 | 接收已成立订单收款事实，解释用户支付状态和商户待清分状态。 | 订单排障、手续费核对、退款和拒付原路径回放。 | transaction、route snapshot、posting plan、ledger entry、余额投影和商户账单。 | 不承接收银台、通道风控、商户入网和 PSP 协议全集。 |
| 提现前冻结后确认出款 | 展示可用余额、冻结金额、出款中和出款结果。 | 出款准入、外部结果处理、失败释放、退回差错和人工处理。 | 冻结单、出款引用、ledger transaction、余额桶、对账批次和审计证据。 | 冻结不是扣款；外部非终态不是出款成功。 |

## 1.2 样例对象、状态和规则总览

| 业务对象 | 字段口径 | 生命周期 | 状态 | 关键规则 |
| --- | --- | --- | --- | --- |
| 商户订单收款事实 | 订单号、capture reference、金额、币种、用户、商户、手续费、幂等键。 | 上层确认 -> 资金指令 -> route -> posting -> ledger entry -> 投影。 | 已确认、准入失败、入账成功、入账失败、待差错处理。 | capture pending 不得当成功；手续费和商户应收不得净额混记。 |
| 提现冻结事实 | 提现单、冻结单、金额、币种、商户 FundingAccount、幂等键。 | 申请 -> 冻结 -> 等待出款结果 -> 解冻、扣划或差错。 | 已冻结、冻结失败、已解冻、已消耗、待人工处理。 | 冻结只做同主体 AVAILABLE 与 FROZEN 转换。 |
| 出款确认事实 | payout reference、外部终态、原冻结单、金额、币种、审计引用。 | 外部终态确认 -> 资金事实 -> 账务处理 -> 对账或差错。 | 待确认、成功、失败、退回、差错。 | submitted、accepted、processing 不得展示为成功。 |

## 1.3 样例规则矩阵

| 规则对象 | 触发条件 | 判断逻辑 | 优先级 | 版本和审计 |
| --- | --- | --- | --- | --- |
| 幂等规则 | 同订单、同提现单或同 payout reference 重复提交。 | 同键同摘要复用原结果；同键不同摘要阻断。 | P0 | 记录 businessSn、idempotencyKey、requestDigest、operator 和 trace。 |
| 金额规则 | 订单收款、手续费、商户应收、冻结、出款参与计算。 | 金额为正、币种一致、金额组件闭合、出款不超过冻结剩余。 | P0 | 记录金额组件、尾差、规则版本和确认方。 |
| 路由规则 | 订单付款、退款、拒付、提现出款或差错补事实。 | 正向可选当前 route；逆向或后续事件必须引用原 route snapshot 或原冻结单。 | P0 | 记录 route snapshot、原事实引用和回放原因。 |
| 外部状态规则 | PSP capture、银行 payout 或外部通道返回状态。 | 只有业务归一后的终态才能驱动资金事实；pending、unknown 只做外部引用和待确认。 | P0 | 记录外部 reference、更新时间、确认方和审计引用。 |
| 运营规则 | 对账差错、出款失败、退回、追偿或补事实。 | 必须有处理单、审批、凭证、白名单命令和重新对账结果。 | P0 | 记录审批号、证据引用、操作者和重新对账结论。 |

## 1.4 运营、数据和验收总览

| 维度 | 最低要求 |
| --- | --- |
| 运营后台 | 能按业务流水、外部 reference、transactionSn、ledgerTransactionSn、entrySn、payout reference 和对账批次排障。 |
| 指标和报表 | 只能消费账本事实、交易投影、余额投影和治理导出，不能反写资金事实。 |
| 审计 | 记录操作者、来源系统、请求摘要、审批号、证据引用、失败原因和人工处理结论。 |
| 风险 | 外部规则、敏感数据、通道状态、出款门禁、手续费拆分和商户可结算口径必须有待确认项或确认方。 |
| 验收 | 每个样例都必须证明状态、金额、账户类型、`normalBalanceSide`、route、posting、ledger entry、projection、借贷平衡、余额影响、幂等、审计和失败无副作用。 |
| 发布 | 样例只能作为接入评审材料；进入生产前仍需 Execution Grant、验证命令、灰度、回滚和 Runbook。 |

## 2. 样例一：商户订单收款

### 2.1 场景结论

| 项 | 结论 |
| --- | --- |
| 业务目标 | 用户完成商户订单支付后，把已成立的收款资金事实交给 wind-funds 记账和投影。 |
| 能力成熟度 | 可进入接入准备；如涉及商户清结算或出款，只能进入专项 Execution Grant。 |
| 推荐入口 | 直接交易 `pay`。 |
| 主要边界 | capture 成功不等于商户可提现；商户待清分、待清算、可结算、结算中、已出款必须分状态。 |
| 不覆盖范围 | 收银台、通道风控、PSP 协议、商户入网、KYC/KYB、卡组织或收单行规则最终判断。 |

### 2.2 资金事实说明卡样例

| 字段 | 样例填写 |
| --- | --- |
| 业务事实名称 | 商户订单收款确认 |
| 业务流水号 | `ORDER-20260526-0001` |
| 幂等键 | `ORDER-20260526-0001-DIRECT-PAY` |
| 请求摘要 | `sha256(orderSn + amount + currency + payer + payee + captureRef)` |
| 业务场景 | 用户订单支付，PSP capture 已形成上层确认事实。 |
| 触发来源 | 业务系统 / 外部结果 |
| 操作者或系统身份 | `system:order-service` |
| 审计引用 | `audit-order-capture-0001` |
| 谁的钱 | 用户用于支付订单的资金，入账后形成商户待清分或待清算资金。 |
| 当前归属 | 用户支付账户或付款资金来源。 |
| 最终归属 | 商户扣除手续费、退款、争议和结算规则后的可结算余额。 |
| 可记账付款主体 | 用户 FundingAccount。 |
| 可记账收款主体 | 商户待清分 FundingAccount、平台手续费账户。 |
| 只读外部引用 | 卡 token、PSP capture reference、订单号、商户号。 |
| 金额和币种 | `USD 100.00`。 |
| 权益、补贴、手续费、税费或尾差 | 手续费 `USD 2.00`，平台收入和商户应收不得净额混记。 |
| 影响账目或余额桶 | 用户 AVAILABLE，商户 CLEARING 或 SETTLEMENT 前置账目，平台手续费收入账目。 |
| DSL 借贷表命中行 | 商户订单收款、手续费独立入账；若含权益金额，还需命中权益金额对应行。 |
| DSL 借贷表不适用行 | 授权完成、冻结控制、出款确认不适用于本收款确认事实。 |
| 账户类型和 normalBalanceSide | 用户 AVAILABLE 和商户待清分或待清算按资金责任口径处理；平台手续费按收入或平台收益口径处理，具体 `normalBalanceSide` 以 DSL 权威表和账本配置为准。 |
| 借贷平衡公式 | 用户付款金额、商户应收和平台手续费分别形成独立 posting 平衡；手续费不得与商户应收净额混成一条不可解释分录。 |
| 余额影响 | 用户可用余额减少，商户待清分或待清算余额增加，平台手续费收入或平台账户余额按配置增加。 |
| 是否需要原 route snapshot | 正向交易使用当前 route；退款、拒付和退费必须引用原 route snapshot。 |
| 失败处理 | 余额不足、错币种、缺账本、幂等冲突或路由失败必须无 route、posting、ledger entry 副作用。 |

### 2.3 概念映射

| 业务对象 | wind-funds 概念 | 说明 |
| --- | --- | --- |
| 订单号 | 业务 reference | 只作为来源引用，不入账。 |
| 用户付款主体 | FundingAccount / spend subject | 需要能解析到账本主体和余额桶。 |
| 商户 | FundingAccount / merchant subject | 进入待清分或待清算账目，不直接等同可提现。 |
| 卡 token | PaymentInstrumentRef | 只做 route 输入和外部引用。 |
| PSP capture reference | ExternalReference | 用于对账和审计，不直接作为账本主体。 |
| 平台手续费 | 平台账户角色和费用账目 | 必须独立表达，不和商户应收净额混记。 |

### 2.5 验收证据

| 证据 | 最低要求 |
| --- | --- |
| 产品证据 | 订单收款不是商户可提现；手续费、补贴、税费和商户应收口径清楚。 |
| DSL 证据 | DIRECT instruction、route snapshot、posting plan、ledger entry 和 projection caseId 可追溯。 |
| 系分证据 | 使用 `FundsDirectTransactionService`，不直接写 ledger entry，不依赖 impl、Entity 或 Mapper。 |
| 测试证据 | 成功链路、余额不足、错币种、幂等冲突、缺账本、路由失败和失败无副作用。 |
| 账务证据 | DSL 借贷表命中行、不适用行、账户类型、`normalBalanceSide`、用户扣减、商户待清分或待清算增加、平台手续费独立入账，posting plan 平衡。 |
| 运营证据 | 可按订单号、PSP reference、transactionSn、ledgerTransactionSn 和 entrySn 排障。 |
| 安全证据 | 不保存完整 PAN、CVV、密钥或证件原文，只保存 token、摘要或脱敏引用。 |

### 2.6 阻断项

| 阻断项 | 处理方式 |
| --- | --- |
| capture 仍是 submitted、accepted、processing、pending 或 unknown。 | 不展示为成功到账，不进入最终入账；等待外部终态、对账或人工确认。 |
| 商户待清分、待清算、可结算和已出款状态混用。 | 回到产品和系分补状态映射。 |
| 手续费、补贴、税费和商户应收净额混记。 | 补金额组件和账务矩阵。 |
| 退款或拒付按当前绑定重新选路。 | 必须引用原 route snapshot。 |

## 3. 样例二：提现前冻结后确认出款

### 3.1 场景结论

| 项 | 结论 |
| --- | --- |
| 业务目标 | 商户发起提现时先冻结可用余额，外部出款成功后再形成独立资金事实。 |
| 能力成熟度 | 冻结可进入接入准备；出款、结算和外部结果处理属于专项 Execution Grant。 |
| 推荐入口 | 余额控制 `freeze` / `unfreeze`，出款确认后使用独立直接交易事实或专项出款流程。 |
| 主要边界 | 冻结不是扣款；外部 submitted 或 accepted 不等于出款成功；失败或退回要释放、冲正或进入差错。 |
| 不覆盖范围 | 银行或 PSP 出款协议、通道额度、cutoff、名单筛查和持牌机构规则最终判断。 |

### 3.2 资金事实说明卡样例

| 字段 | 冻结事实 | 出款确认事实 |
| --- | --- | --- |
| 业务事实名称 | 提现前冻结 | 出款成功确认 |
| 业务流水号 | `WD-20260526-0001-FREEZE` | `WD-20260526-0001-PAYOUT` |
| 幂等键 | `WD-20260526-0001-FREEZE` | `WD-20260526-0001-PAYOUT` |
| 金额和币种 | `USD 80.00` | `USD 80.00` |
| 可记账主体 | 商户 FundingAccount | 商户 FundingAccount、平台出款中或在途账户角色 |
| 影响余额桶 | AVAILABLE -> FROZEN | FROZEN -> IN_TRANSIT 或按专项出款事实处理 |
| DSL 借贷表命中行 | 余额控制冻结行。 | 出款确认或结算出款行；是否允许进入该行由专项 Execution Grant 确认。 |
| DSL 借贷表不适用行 | 商户收款、授权完成、清算确认不适用于冻结事实。 | 冻结行不再重复表达真实资金离开；外部非终态不适用于出款成功确认。 |
| 账户类型和 normalBalanceSide | 商户 AVAILABLE 和 FROZEN 是同主体余额桶，账户类型和 `normalBalanceSide` 以 DSL 权威表和账本配置为准。 | 商户 FROZEN、IN_TRANSIT 或外部出款相关账户按专项设计确认，账户类型和 `normalBalanceSide` 以 DSL 权威表和账本配置为准。 |
| 借贷平衡公式 | 同主体 AVAILABLE 减少、FROZEN 增加，独立 posting 平衡，不产生跨主体价值转移。 | 引用原冻结单释放或消耗 FROZEN，进入 IN_TRANSIT 或出款事实，独立 posting 平衡。 |
| 余额影响 | 商户 AVAILABLE 减少、FROZEN 增加。 | 外部终态成功后才进入出款中、在途或资金离开表达；pending 不改变成功余额口径。 |
| 原事实引用 | 无 | 原冻结单 `WD-20260526-0001-FREEZE` |
| 外部引用 | 提现申请单 | payout reference、银行流水或 PSP payout reference |
| 展示口径 | 已冻结，不能提现但未扣款。 | 只有外部终态成功后才能展示为出款成功。 |
| 失败处理 | 余额不足、重复冻结、错币种、缺账户无副作用。 | submitted、accepted、processing 不当成功；失败或退回必须释放、冲正或差错。 |

### 3.4 验收证据

| 证据 | 最低要求 |
| --- | --- |
| 产品证据 | 用户、商户和运营能区分已冻结、出款处理中、出款成功、出款失败和退回。 |
| DSL 证据 | freeze、unfreeze、payout result 或直接交易事实的 caseId 可追溯。 |
| 系分证据 | 冻结只走余额控制；出款确认必须受出款准入门禁、外部规则和专项授权约束。 |
| 测试证据 | 冻结成功、冻结失败无副作用、重复冻结、解冻不超额、出款 pending 不成功、出款失败释放或差错。 |
| 账务证据 | DSL 借贷表命中行、不适用行、账户类型、`normalBalanceSide`、冻结只做 AVAILABLE 与 FROZEN 同主体转换；出款成功才表达真实资金离开或在途。 |
| 运营证据 | 可按提现单、冻结单、payout reference、ledgerTransactionSn、reconciliationBatchSn 排障。 |
| 安全证据 | 出款账户、收款端点、名单筛查、外部规则、审批和证据引用必须脱敏并审计。 |

### 3.5 阻断项

| 阻断项 | 处理方式 |
| --- | --- |
| 冻结被设计成扣款或跨主体转移。 | 阻断，回到余额控制语义。 |
| 出款 submitted、accepted、processing 被展示为成功。 | 阻断，补外部状态展示口径。 |
| 缺少原冻结单就发起出款确认。 | 阻断或人工补证据，不得重新选路兜底。 |
| 出款规则、名单筛查、cutoff、额度或外部规则未确认。 | 只能做设计或 TDD 分析，不得提交外部出款。 |

## 4. 样例使用方式

| 使用者 | 使用方式 |
| --- | --- |
| 产品和业务 | 先把自己的业务动作改写成本文的资金事实口径，再判断是否应该进入 wind-funds。 |
| 研发和架构 | 从伪请求中抽取公共契约影响、服务入口、幂等、事务边界和 Execution Grant 写入范围。 |
| 测试 | 把 `mustHave`、`mustProve`、`mustFailWhen` 转成目标测试资产和红线用例。 |
| 运营、财务、风控、安全 | 检查外部引用、审批、证据、敏感数据、Runbook 和人工处理入口是否完整。 |

样例中的字段可以按业务裁剪，但不能裁剪资金不变量：主体、账户类型、`normalBalanceSide`、金额、币种、route、posting、ledger entry、projection、借贷平衡、余额影响、幂等、审计和失败无副作用。凡涉及资金变化，都必须回挂 DSL 资金场景借贷平衡与账务期望表，说明命中行和不适用行。
