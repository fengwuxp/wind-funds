# wind-funds 接入申请模板

## 使用说明

本模板用于业务接入方提交接入申请。填写后应回挂 PRD、DSL、系分、TDD 和 Execution Grant，不替代这些权威设计文档。

如果某项暂时无法确认，填写“待确认”，并说明确认方、影响范围和未确认期间的处理方式。涉及真实资金、客户资金、商户待结算资金、敏感数据、跨境、外汇、ACH、银行、PSP、卡组织或持牌规则时，不得把待确认项写成已确认结论。

## 提交前检查

| 检查项 | 通过标准 | 不通过时处理 |
| --- | --- | --- |
| 资金事实说明卡 | 每个资金动作都有独立说明卡，且主体、账户类型、`normalBalanceSide`、金额、币种、幂等、借贷平衡、余额影响、失败处理和验收证据完整。 | 退回补卡，不进入接入评审。 |
| 资金不变量和借贷平衡引用 | 每个资金变化都已回挂 DSL 资金场景借贷平衡与账务期望表，说明命中行、不适用行、账户类型、`normalBalanceSide`、借贷平衡和余额影响。 | 退回补账务口径，不进入 Execution Grant。 |
| 业务目标和非目标 | 能说明为什么接入、接什么、不接什么。 | 回到产品澄清。 |
| 能力成熟度 | 能判断可进入接入准备、专项 Execution Grant、仅 TDD 分析或阻断。 | 回到接入指南 3 章补判断。 |
| 内部能力选择 | 能说明本接入使用 FundingAccount、CreditAccount、BudgetGroup 还是 PaymentInstrument；VCC 预付卡、共享卡等产品形态不会自动创建账户。 | 退回补概念映射，不进入 Execution Grant。 |
| 公共契约影响 | 明确是否新增或修改接口、Request、Query、DTO、Spec、Enum、Error。 | 需要 Execution Grant 后才能编码。 |
| 表和配置影响 | 明确是否新增或修改表、H2 schema、测试资源或运行时配置。 | 需要 Execution Grant 后才能编码。 |
| 外部规则和敏感数据 | 已记录规则来源、版本或发布日期、生效日期、适用范围、核验日期、确认方、确认状态和脱敏边界。 | 未确认前不得驱动自动资金处理。 |

## 结论判定规则

| 结论 | 可填写条件 | 不允许事项 |
| --- | --- | --- |
| 通过 | 业务事实、主体、资金归属、账户类型、`normalBalanceSide`、route、posting、entry、projection、借贷平衡、余额影响、幂等、审计、外部规则和验收证据在本次范围内闭合。 | 不得把通过等同于生产 Done。 |
| 带条件通过 | 主链路可接入，但存在不影响核心资金不变量的待确认项。 | 编码不得越过条件边界，未确认项不得自动资金处理。 |
| 阻断 | 主体不清、资金归属不清、路径不可追溯、外部规则未确认、敏感数据越界、验收不可测或需要绕过账本。 | 不得进入 Execution Grant。 |

## 必须阻断的情况

| 情况 | 处理 |
| --- | --- |
| 业务事实只是页面动作、审批中、通道处理中或外部非终态。 | 阻断，回到业务系统或通道适配层。 |
| 外部账户、支付工具、业务订单或经营主体被直接作为 ledger subject。 | 阻断，补概念映射和账户建模。 |
| VCC 预付卡、共享卡、卡组或持卡人被自动建成资金账户、信用账户或预算组。 | 阻断，补支付工具、绑定、资金来源关系和内部能力选择。 |
| 需要直接改余额、改投影、改历史分录或线下修数。 | 阻断，回到资金事实和账务路径设计。 |
| 清结算、对账、出款或归档重放被当作已生产完成能力。 | 阻断，改为专项 Execution Grant 或 TDD 分析。 |
| 外部规则、敏感数据、权限审计或 Runbook 缺失。 | 带条件通过或阻断，不能生产启用。 |
