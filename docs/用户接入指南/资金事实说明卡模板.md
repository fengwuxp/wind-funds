# 资金事实说明卡模板

## 使用说明

资金事实说明卡用于判断某个业务动作是否应该进入 wind-funds。填写不完整时，不应进入编码；只能回到业务澄清、产品设计、DSL 拆解、系分补充或 TDD 分析。

本说明卡只描述已经成立或可被上层业务归一的资金事实，不接收页面动作、审批中状态、通道处理中状态或外部非终态作为已入账事实。

## 填写前检查

| 检查项 | 通过标准 | 不通过时处理 |
| --- | --- | --- |
| 业务目标 | 能说明为什么接入 wind-funds，以及接入后要解决什么资金问题。 | 回到产品设计补目标和非目标。 |
| 用户价值 | 能说明用户、商户、运营、财务、风控或业务系统如何理解结果。 | 补使用者解释视图。 |
| 非目标 | 能说明哪些能力不由 wind-funds 承接。 | 补边界，避免把业务审批、外部协议或风控决策沉入资金底座。 |
| 资金事实 | 业务动作已经成立或已被上层业务归一。 | 停留在业务系统或通道适配层。 |
| 主体和资金归属 | 能说清谁的钱、当前属于谁、最终归属谁。 | 阻断接入，不进入 route 或 posting。 |
| 可记账主体 | 能解析为 FundingAccount、CreditAccount、BudgetGroup 或平台账户角色。 | 先补账户建模或工具绑定。 |
| 内部能力选择 | 能说明本动作使用 FundingAccount、CreditAccount、BudgetGroup 还是 PaymentInstrument；VCC 预付卡、共享卡等产品形态不会反推账户类型。 | 退回补概念映射和 VCC/支付工具边界。 |
| 借贷权威表 | 能回挂 DSL 的资金场景借贷平衡与账务期望表，说明命中行、不适用行、账户类型、`normalBalanceSide` 和余额影响。 | 退回补账务口径，不进入 Execution Grant。 |
| 外部规则 | 规则来源、版本或发布日期、生效日期、适用范围、核验日期和确认方清楚。 | 未确认前只能做设计或 TDD 分析。 |

## 必须退回或阻断的情况

| 情况 | 处理 |
| --- | --- |
| 不能说明谁的钱、当前归属和最终归属。 | 阻断。 |
| 只有外部账户、支付工具或业务订单，不能解析可记账主体。 | 退回补账户建模。 |
| 因 VCC 预付卡、共享卡、卡组或持卡人自动创建 FundingAccount、CreditAccount 或 BudgetGroup。 | 阻断，回到支付工具、绑定和内部能力选择。 |
| 外部 submitted、accepted、processing、pending 或 unknown 被当成成功。 | 阻断。 |
| 计划直接写 ledger entry、改余额、改投影或线下修数。 | 阻断。 |
| 涉及敏感数据但没有脱敏、导出、日志和证据最小化方案。 | 阻断。 |
| 只写接口成功，不证明余额桶、posting plan、ledger entry、projection、幂等和审计。 | 退回补验收证据。 |
