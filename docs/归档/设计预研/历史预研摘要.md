# 历史预研摘要

## 1. 文档定位

本文用于快速定位早期长篇预研材料中的稳定结论和当前承接入口。归档原文仍保留在本目录中，但均已降权为历史参考，不作为当前 PRD、DSL、系分、TDD、接入指南、编码准入或生产交付依据。

当前权威口径以 [../../README.md](../../README.md) 以及产品设计、DSL 设计、系分设计、TDD 设计和用户接入指南为准。本文与当前权威设计包冲突时，以当前权威设计包为准。

## 2. 已吸收的稳定结论

| 历史主题 | 稳定结论 | 当前承接入口 |
| --- | --- | --- |
| 三类业务支撑评估 | `wind-funds` 定位为支付资金底座，不是完整 VCC 发卡处理商、全球账户产品或收单产品。三类业务通过场景交易能力包接入统一资金内核。 | 产品设计 01、06、07、08；系分设计 01、02、03、04、05；用户接入指南。 |
| 三类业务能力地图 | 交易层不完全通用；钱包、账本、账目、余额投影、清分、清算、结算、对账、归档和重放应统一设计、统一实现。 | 产品设计 README 的 P0/P1/P2 顺序；产品设计 01；系分设计 README；TDD 设计。 |
| 收单业务边界 | `wind-funds` 只支撑收单产生后的资金事实、商户资金账户、清结算、对账、出款、争议资金影响、投影和归档；不承接商户入网、收银台、支付网关、通道协议、PCI 敏感数据或完整支付尝试生命周期。 | 产品设计 08、产品边界能力图、系分设计 03、TDD 设计。 |
| 商品订单交易体系边界 | 商品订单、支付意图、履约、售后和退款申请属于上层业务系统；`wind-funds` 只提供资金指令、路由、账本、账目、清结算、对账和投影能力。 | 产品设计 README、系分设计 README；如需重构订单交易体系，应在上层业务项目独立维护 PRD 和系分设计。 |
