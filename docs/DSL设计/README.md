# DSL 设计

本目录是 `wind-funds` 支付资金底座 DSL 的最终版入口。

权威文档：

- `支付资金底座最终DSL设计.md`

## 定位

DSL 设计归属为**系分设计中的领域 DSL 契约规范**，不是产品 PRD，也不是某个实现类的详细设计。它是产品语义到工程契约之间的领域契约层：

- 向上承接 `docs/产品设计` 中的业务事实、主体、账户、账目、资金流、异常路径和验收红线。
- 向下指导系分设计定义模块、接口、枚举、DTO、表结构、契约测试和 TDD 样例。
- 不替代清结算、对账、归档、指标、接口、DDL、迁移、监控和发布回滚等能力域系分设计。

## 使用方式

1. 产品评审时，重点看定位、设计意图、核心语义和场景覆盖。
2. 系分设计时，重点看 DSL 对象结构、不变量、系分指导和待系分闭合点；OpenSpec 和代码对齐在系分阶段处理。
3. 测试设计时，重点看场景覆盖、JSON 契约样例、TDD 和评审清单。
4. 编码前，必须先完成对应能力域的系分设计、OpenSpec change、JSON 契约样例、TDD 用例和迁移/回滚方案；本文不直接给出编码批准。

## JSON 使用边界

本文档写给人读，优先用中文叙述、表格和流程图解释设计目标、语义边界和流程。只有真正的 DSL 契约对象和场景夹具使用 `json` 代码块，便于后续转成契约样例、测试资源或 OpenSpec 输入。

文档中的 JSON 是契约表达，不等同于 Controller 报文或数据库结构。设计目标、总体流程、评审清单和禁止清单不应强行 JSON 化。

## 结论

当前 DSL 设计可以作为系分设计、OpenSpec、JSON 契约测试和 TDD 契约设计输入；不能直接作为整包编码或生产上线批准。
