# 优惠券、代金券资金语义产品设计

## 1. 文档定位

本文是优惠券、代金券进入支付资金底座时的产品层评审稿，用于先确认业务语义、职责边界、资金流表达、退款处置、清结算影响和实际场景范围。

本文暂不直接修改现有 PRD、DSL、系分、TDD 和 OpenSpec 文档；后续如确认纳入目标态，再按“影响清单”分批合入权威设计。

| 维度 | 说明 |
| --- | --- |
| 文档性质 | 独立产品设计评审稿。 |
| 覆盖范围 | 直接交易、授权交易、退款、撤销、清结算、对账、投影中的优惠券、代金券资金语义。 |
| 不覆盖范围 | 营销活动配置、领券发券、券可用性计算、复杂叠加规则、券包运营、推荐策略、增长策略。 |
| 设计目标 | 把优惠券和代金券从“营销规则”转成资金底座可识别、可快照、可入账、可退款、可清结算、可对账的金额组件。 |
| 重要边界 | 本文不替代财务、会计、税务、法务或合规最终结论；补贴成本、沉淀收益、负债释放等口径需专业确认。 |

一句话结论：资金底座不做优惠券规则引擎，只接收业务侧已经确认的权益结果快照，并负责把权益结果转成稳定的资金语义。

## 2. 背景和问题

现有支付资金底座已经要求本金、手续费、成本、补贴、追偿和调账必须拆分，也要求退款、撤销、拒付、清结算和对账基于原 route snapshot 回放。

优惠券和代金券加入后，单纯的“订单金额”和“支付金额”不足以解释后续资金行为。典型问题包括：

1. 用户实付减少了，商户应收到底减少还是由平台补贴补足。
2. 优惠券不退时，用户侧不返券和资金侧不冲补贴是不是同一件事。
3. 授权交易是否应该在授权时核销券，还是只做权益占用。
4. 部分退款时，先退现金、先退券、按比例退还是按商品行退。
5. 清结算时，商户看到的是原价、优惠后金额、平台补贴金额，还是可结算净额。
6. 对账时，营销系统核销结果、订单金额、资金分录、商户清算明细如何核对。

如果没有独立设计，优惠券容易被错误地合入本金，导致退款超额、商户清算失真、平台补贴成本不可解释、代金券负债被误当成营销折扣。

## 3. 设计目标和非目标

### 3.1 设计目标

| 目标 | 说明 |
| --- | --- |
| 金额可拆 | 订单原始金额、用户实付、商户让利、平台补贴、代金券核销、手续费、成本可拆分。 |
| 规则可追溯 | 每个权益组件保留规则版本、权益引用、核销或占用凭证、退款处置。 |
| 资金可解释 | 每个权益组件说明是否产生资金分录、由谁承担、给谁受益、退款时如何处理。 |
| 退款可重放 | 退款、撤销、过期、拒付只重放原权益快照，不重新计算优惠券。 |
| 清结算可核对 | 商户应收、平台补贴、商户让利、代金券核销、补贴冲回和券不退都可形成清结算金额项。 |
| 对账可闭环 | 能与订单、营销权益系统、账本、清结算和财务报表形成可解释差异。 |

### 3.2 非目标

| 非目标 | 说明 |
| --- | --- |
| 不内建营销规则引擎 | 不计算是否可用券、不判断最优券、不处理叠加优先级。 |
| 不维护券生命周期全量状态 | 领券、发券、过期、库存、活动预算、用户券包仍由营销或权益系统负责。 |
| 不替代订单价格体系 | 商品行价格、促销价、会员价、满减、运费税费等先由订单侧形成价格结果。 |
| 不替代财务会计判断 | 补贴成本、商户收入、平台收入、沉淀收益、负债释放由财务会计确认。 |
| 不把所有代金券都等同优惠券 | 储值、预付、礼品卡型代金券可能是负债或余额能力，需要单独资金账户语义。 |

## 4. 职责边界

优惠券和代金券相关能力按“营销权益计算”和“资金语义承接”分层。资金底座只承接已经决策完成的权益结果。

| 领域 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 营销 / 权益系统 | 发券、领券、券库存、适用条件、叠加规则、权益占用、核销、释放、退券、作废、活动预算规则。 | 不直接写资金账本，不生成商户清算分录，不决定资金账户入账路径。 |
| 订单 / 交易业务系统 | 计算订单原价、优惠后价格、用户实付、商品行分摊、用户选择权益、支付意图和业务快照。 | 不绕过资金底座直接改余额，不直接生成 ledger entry。 |
| 支付资金底座 | 接收金额组件和权益快照，生成 route snapshot、posting plan、ledger entry、退款重放、清结算金额项和投影口径。 | 不重新计算券规则，不判断券是否可用，不维护券完整生命周期。 |
| 账本能力 | 记录用户实付、商户待清算、平台补贴、代金券负债、手续费、退款冲回等账务事实。 | 不解释营销规则，不根据活动条件改写历史账。 |
| 清结算与对账 | 按快照拆分商户应收、商户让利、平台补贴、代金券核销、补贴冲回、券不退等金额项。 | 不补算优惠金额，不替代营销系统核销对账。 |
| 财务 / 会计 / 合规 | 确认补贴成本、销售收入、负债释放、不退券沉淀、税务和合规口径。 | 不由资金底座自行决定专业分类。 |

职责边界规则：

1. 营销系统输出“权益决策结果”，资金底座输出“资金处理结果”。
2. 资金底座保存权益快照，不保存完整营销规则。
3. 退款时资金底座只依据原权益快照执行，不重新调用营销系统计算优惠。
4. 营销系统可参与退券、释放占用、核销撤销，但不能直接修改资金账本。
5. 如果代金券具有预付、储值、礼品卡或余额属性，必须先确认资金归属和负债口径，再进入资金账户模型。

## 5. 核心概念

| 概念 | 产品定义 | 资金底座处理口径 |
| --- | --- | --- |
| 订单原始金额 | 未扣减权益前，订单侧确认的应计价金额。 | 作为金额闭合和展示口径，不一定直接入账。 |
| 用户实付金额 | 用户通过余额、银行卡、授信或其他支付工具实际支付的金额。 | 必须形成用户侧付款或授权占用资金路径。 |
| 商户优惠券 | 商户承担的让利，降低商户应收。 | 通常不产生独立资金分录，只影响商户应收和展示。 |
| 平台补贴券 | 平台承担的补贴，用户少付但商户可能仍按补贴后规则收款。 | 需要形成平台补贴资金路径或补贴成本口径。 |
| 普通代金券 | 平台或业务发放的抵扣权益，不一定代表用户预付资金。 | 视承担方处理为平台补贴或商户让利。 |
| 储值 / 预付代金券 | 用户已预先支付或平台形成待履约负债的权益。 | 应作为负债、预收或用户权益余额处理，不可简单当营销优惠。 |
| 权益快照 | 本次交易实际使用权益的结果快照。 | 后续退款、撤销、清结算、对账的唯一依据之一。 |
| 权益金额组件 | 一笔交易中由优惠券或代金券形成的金额组成。 | 决定是否入账、谁承担、谁受益、退款如何处理。 |
| 退款处置规则 | 权益组件在退款、撤销、授权取消时的处理规则。 | 组件级快照，不能使用全局开关替代。 |

## 6. 金额模型

### 6.1 金额闭合公式

交易付款场景的产品金额应满足：

```text
orderAmount = userPayAmount
            + merchantDiscountAmount
            + platformSubsidyAmount
            + voucherRedeemAmount
            + otherBenefitAmount
```

商户可清算金额不一定等于订单原始金额，需要按业务合同和权益承担规则计算：

```text
merchantReceivableAmount = orderAmount
                         - merchantDiscountAmount
                         + platformSubsidyToMerchantAmount
                         + voucherSettlementAmount
                         - merchantFeeAmount
                         - merchantDeductionAmount
```

用户可退金额不一定等于订单原始金额，应按原快照和退款处置规则计算：

```text
userRefundCashAmount <= userPayAmount - alreadyRefundedCashAmount
benefitRefundAmount 由每个权益组件的 refundDisposition 决定
```

### 6.2 金额组件分类

| 组件类型 | 谁承担 | 谁受益 | 是否产生资金分录 | 典型账务影响 |
| --- | --- | --- | --- | --- |
| PRINCIPAL | 用户或付款方 | 商户或收款方 | 是 | 用户 AVAILABLE 减少，商户 CLEARING 增加。 |
| MERCHANT_DISCOUNT | 商户 | 用户 | 通常否 | 降低商户应收，不单独转移资金。 |
| PLATFORM_SUBSIDY | 平台 | 用户或商户 | 是 | 平台补贴账户或成本账户向商户 CLEARING 形成补足。 |
| PLATFORM_COUPON_NO_SETTLEMENT | 平台 | 用户 | 视规则而定 | 用户少付，商户也少收；平台不补足商户。 |
| VOUCHER_REDEEM | 用户历史权益、平台负债或业务权益池 | 用户或商户 | 视代金券属性而定 | 预付型通常需要冲减负债并增加商户 CLEARING。 |
| FEE | 商户、用户或平台 | 平台 | 是 | 平台 FEE 增加。 |
| CHANNEL_COST | 平台或商户 | 通道或成本主体 | 是或清结算项 | 成本需和本金、补贴分开。 |
| TAX_OR_SERVICE_ADJUSTMENT | 规则指定主体 | 税费或服务主体 | 视规则而定 | 进入单独金额组件和财务口径。 |

### 6.3 权益组件必备口径

每个权益金额组件至少需要描述以下产品口径：

| 口径 | 说明 |
| --- | --- |
| componentType | 组件类型，例如商户让利、平台补贴、代金券核销。 |
| componentAmount | 组件金额、币种和精度。 |
| bearer | 承担方，例如商户、平台、用户历史权益、第三方合作方。 |
| beneficiary | 受益方，例如用户、商户、平台。 |
| settlementEffect | 是否影响商户应收、是否补足商户、是否仅影响展示。 |
| ledgerEffect | 是否产生账本分录，若产生，应进入哪类资金路径。 |
| benefitRef | 券、活动、规则、核销或占用引用。 |
| ruleVersion | 权益计算和退款规则版本。 |
| refundDisposition | 退款处置，例如返券、作废、不退、冲补贴、不冲补贴。 |
| partialRefundStrategy | 部分退款策略，例如按商品行、按比例、用户实付优先、权益优先。 |

## 7. 退款和撤销处置规则

### 7.1 用户侧和资金侧必须分离

“优惠券不退”至少包含两个问题：

1. 用户侧是否返还券或恢复权益。
2. 资金侧是否冲回补贴、冲减商户应收、释放负债或进入损益。

这两个问题不能用一个布尔字段表达。

| 用户侧处置 | 资金侧处置 | 说明 |
| --- | --- | --- |
| 返券 | 冲回补贴 | 常见于全额退款且券仍有效。 |
| 返券 | 不冲回补贴 | 需要业务和财务明确，可能造成重复补贴风险。 |
| 不返券 | 冲回补贴 | 用户不拿回券，但平台从商户清算或补贴成本中冲回。 |
| 不返券 | 不冲回补贴 | 平台承担损失或按活动成本确认，必须财务确认。 |
| 作废 | 释放负债 | 适用于部分预付或未履约权益，需确认负债口径。 |
| 不返券 | 释放或转损益 | 适用于储值、礼品卡、过期权益等特殊场景，需专业确认。 |

### 7.2 退款处置枚举口径

| 处置口径 | 产品含义 | 适用场景 |
| --- | --- | --- |
| REISSUE | 退款后返还或重发权益。 | 普通优惠券全额退款、活动允许退券。 |
| RELEASE_HOLD | 授权取消时释放权益占用，不核销。 | 授权交易未完成。 |
| VOID | 权益作废，不再可用。 | 不退券活动、过期券、一次性权益。 |
| NO_REFUND | 用户侧不返还权益。 | 活动规则明确不退。 |
| REVERSE_SUBSIDY | 资金侧冲回平台补贴或商户补足。 | 平台补贴随退款冲回。 |
| RETAIN_SUBSIDY | 资金侧不冲回补贴。 | 平台承担补贴成本，需财务确认。 |
| REDUCE_MERCHANT_RECEIVABLE | 退款时减少商户应收或待清算金额。 | 商户让利和商户承担部分退款。 |
| RESTORE_PREPAID_LIABILITY | 恢复用户预付权益或负债余额。 | 储值、礼品卡、预付代金券允许退回。 |
| RELEASE_TO_INCOME_OR_BREAKAGE | 不退回预付权益，转收入或沉淀口径。 | 需财务、合规、合同确认。 |

实际产品设计中，一个权益组件可能同时有用户侧处置和资金侧处置，例如 `NO_REFUND + REVERSE_SUBSIDY`。

### 7.3 部分退款策略

| 策略 | 产品含义 | 风险点 |
| --- | --- | --- |
| ITEM_LINE_BASED | 按商品行归属退款，退哪件商品就处理该商品分摊权益。 | 需要订单侧提供商品行分摊快照。 |
| PROPORTIONAL | 按退款金额占原订单金额比例分摊实付和权益。 | 小数尾差和多次退款累计需要明确。 |
| CASH_FIRST | 优先退用户实付现金，权益保持不变或最后处理。 | 可能导致平台或商户承担超预期。 |
| BENEFIT_FIRST | 优先消耗权益退款空间，现金退款靠后。 | 用户体验可能较差，需要前台说明。 |
| NON_REFUNDABLE_BENEFIT_FIRST | 不退权益先确认不可退部分，再计算现金可退。 | 需要明确展示，避免用户误解。 |

退款策略必须进入原交易快照。后续退款不能根据当前活动规则重新判断。

## 8. 直接交易资金流设计

### 8.1 商户优惠券

示例：订单 100，商户优惠券 20，用户实付 80，平台手续费 2。

| 项目 | 金额 |
| --- | --- |
| 订单原始金额 | 100 |
| 用户实付 | 80 |
| 商户让利 | 20 |
| 商户应收毛额 | 80 |
| 平台手续费 | 2 |
| 商户待清算 | 78 |

资金语义：

1. 用户 AVAILABLE 减少 80。
2. 商户 CLEARING 增加 78。
3. 平台 FEE 增加 2。
4. 商户优惠券 20 不产生独立资金分录，只作为金额组件、商户应收计算和展示依据。

退款时：

| 退款场景 | 处理 |
| --- | --- |
| 全额退款且券可退 | 用户现金退 80，券返还或重发，商户 CLEARING 冲回 78，手续费按费用规则处理。 |
| 全额退款且券不退 | 用户现金退 80，券不返还；商户 CLEARING 冲回 78；商户让利不产生资金返还。 |
| 部分退款 | 按商品行或分摊规则计算现金退款和商户应收冲回；不退券时只记录权益不可退金额。 |

### 8.2 平台补贴券，补足商户

示例：订单 100，平台补贴券 20，用户实付 80，平台手续费 2，商户按 100 计收款。

| 项目 | 金额 |
| --- | --- |
| 订单原始金额 | 100 |
| 用户实付 | 80 |
| 平台补贴 | 20 |
| 商户应收毛额 | 100 |
| 平台手续费 | 2 |
| 商户待清算 | 98 |

资金语义：

1. 用户 AVAILABLE 减少 80。
2. 平台补贴资金或补贴成本组件承担 20。
3. 商户 CLEARING 增加 98。
4. 平台 FEE 增加 2。
5. 补贴组件必须可在清结算和财务报表中单独识别。

退款时：

| 退款场景 | 用户侧 | 资金侧 |
| --- | --- | --- |
| 可退券且冲补贴 | 退现金 80，返券或重发权益。 | 冲回商户 CLEARING 98，平台补贴 20 冲回，手续费按规则处理。 |
| 不退券但冲补贴 | 退现金 80，不返券。 | 平台补贴 20 冲回，商户应收按退款冲回。 |
| 不退券且不冲补贴 | 退现金 80，不返券。 | 平台补贴不冲回，商户是否保留补贴需财务和商户合同确认。 |
| 部分退款 | 按原快照分摊现金和补贴。 | 对应比例或商品行的补贴冲回或保留。 |

### 8.3 平台补贴券，不补足商户

示例：订单 100，平台优惠券 20，用户实付 80，商户按 80 收款。

资金语义：

1. 用户 AVAILABLE 减少 80。
2. 商户 CLEARING 按 80 减手续费后增加。
3. 平台优惠券仅影响用户价格，不补足商户，不产生平台到商户的资金路径。
4. 该场景本质更接近平台让用户少付但商户也按优惠后金额成交，必须由业务合同确认。

风险点：

1. 用户看到“平台券”，商户是否承担降价需明确。
2. 如果平台实际承诺补商户，则不能使用该口径。
3. 清结算展示必须说明商户应收基准是优惠后金额。

### 8.4 预付 / 储值 / 礼品卡型代金券

示例：订单 100，用户使用礼品卡或储值代金券 20，现金支付 80，手续费 2。

资金语义：

1. 用户现金账户 AVAILABLE 减少 80。
2. 用户预付权益、礼品卡余额或平台负债减少 20。
3. 商户 CLEARING 按 100 减手续费后增加 98。
4. 平台 FEE 增加 2。

产品边界：

| 问题 | 要求 |
| --- | --- |
| 是否是用户预付资金 | 如果是，必须纳入负债、余额或预收待付口径。 |
| 是否可退 | 由合同、活动规则、财务和合规确认。 |
| 是否允许过期沉淀 | 不能由资金底座自行判断，需专业确认。 |
| 是否与普通券混用 | 不建议混用；普通券是优惠权益，储值券可能是资金权益。 |

退款时：

| 处置 | 资金结果 |
| --- | --- |
| 退回代金券余额 | 恢复预付权益或负债余额，商户 CLEARING 冲回。 |
| 不退代金券 | 不恢复用户权益；已核销负债如何处理需财务确认。 |
| 现金补退 | 若业务允许把代金券退成现金，必须作为高风险场景单独审批。 |

## 9. 授权交易资金流设计

授权交易中的优惠券和代金券最容易出问题：授权成功不等于交易完成，因此不建议在授权批准时直接核销不可退权益。

### 9.1 推荐模式：授权时占用权益，完成时核销权益

| 阶段 | 用户资金 | 优惠券 / 代金券 | 资金底座结果 |
| --- | --- | --- | --- |
| authorize | 用户现金、额度或预算进入 AUTHORIZATION 占用。 | 营销系统返回 benefitHoldId，权益进入占用。 | 保存授权快照和权益占用快照，不核销券。 |
| reversal | 释放 AUTHORIZATION。 | 释放权益占用。 | 不产生最终消费，不生成商户 CLEARING。 |
| expire | 释放剩余 AUTHORIZATION。 | 释放剩余权益占用或按过期规则处理。 | 状态为 EXPIRED，不等同撤销。 |
| settle | AUTHORIZATION 转入商户 CLEARING。 | 权益核销或转资金组件。 | 生成结算金额组件和账本分录。 |
| settleRefund | 基于 settle 快照退款。 | 按 settle 时权益快照处理退券、作废、冲补贴。 | 不重新计算权益。 |

该模式适合绝大多数授权场景，因为可以避免“授权成功但用户取消，券已经不退”的争议。

### 9.2 特殊模式：授权时即核销权益

只有在业务明确要求“一旦授权成功，券立即消耗且不可退”时才使用。

必须补充的产品口径：

| 口径 | 说明 |
| --- | --- |
| authorizeBenefitDisposition | 授权成功时权益是否核销、占用、作废。 |
| authorizationCancelDisposition | 授权撤销或过期时权益是否释放、返还、作废、不退。 |
| customerNotice | 用户是否在支付前明确看到授权后不退券规则。 |
| riskApproval | 是否需要业务、法务、客服和财务确认。 |

风险：

1. 用户取消授权但券不退，客服争议会增加。
2. 授权失败和授权拒绝必须确保不核销权益。
3. 授权超时、外部状态不明、重复回调时需要严格幂等。

### 9.3 授权拒绝红线

| 场景 | 产品要求 |
| --- | --- |
| 余额不足拒绝 | 不生成 route、posting plan、ledger entry；不得核销券。 |
| 风控拒绝 | 不生成账务路径；券占用必须释放或从未占用。 |
| 权益不可用 | 授权拒绝或退回业务侧重新选券；不得生成资金账。 |
| 部分权益占用失败 | 整体授权失败或进入业务重试，不得只占资金不占券。 |

## 10. 清结算与对账设计

### 10.1 清结算金额项

优惠券和代金券进入清结算后，不能只展示一个“订单金额”。至少需要以下金额项：

| 金额项 | 含义 | 来源 |
| --- | --- | --- |
| orderAmount | 订单原始金额。 | 订单快照。 |
| userPayAmount | 用户实付金额。 | 资金交易或授权完成快照。 |
| merchantDiscountAmount | 商户让利金额。 | 权益组件快照。 |
| platformSubsidyAmount | 平台补贴金额。 | 权益组件和补贴资金路径。 |
| voucherRedeemAmount | 代金券核销金额。 | 权益组件和代金券账户或负债路径。 |
| merchantReceivableAmount | 商户应收毛额。 | 清结算规则。 |
| merchantFeeAmount | 商户承担手续费。 | 费用组件。 |
| merchantClearingAmount | 商户待清算或可清算金额。 | 账本和清分规则。 |
| benefitRefundAmount | 退款涉及的权益金额。 | 原快照和退款处置。 |
| subsidyReversalAmount | 补贴冲回金额。 | 退款处置和清结算规则。 |
| nonRefundableBenefitAmount | 不退券或不返还权益金额。 | 退款处置快照。 |

### 10.2 对账对象

| 对账对象 | 对账内容 |
| --- | --- |
| 订单系统 | 订单原始金额、优惠后金额、商品行分摊、退款商品行。 |
| 营销 / 权益系统 | 权益占用、核销、退券、作废、活动预算扣减。 |
| 资金交易 | 用户实付、平台补贴、代金券核销、退款、撤销。 |
| 账本系统 | 用户、商户、平台、负债账户的分录和平衡。 |
| 清结算系统 | 商户应收、待清算、可结算、补贴冲回、扣减项。 |
| 财务报表 | 补贴成本、手续费收入、负债释放、沉淀收益、差错挂账。 |

### 10.3 差错类型

| 差错 | 示例 | 处理方向 |
| --- | --- | --- |
| 订单优惠金额和权益核销不一致 | 订单显示用券 20，营销核销 10。 | 阻断清算或生成差错单，不能静默按任一方入账。 |
| 资金补贴入账和营销预算不一致 | 平台补贴入账 20，活动预算只扣 15。 | 对账差错，明确责任方和调账路径。 |
| 不退券规则未进入快照 | 退款时当前活动规则显示不退，但原交易无记录。 | 不得按当前规则重算，进入人工处理。 |
| 商户让利误记平台补贴 | 商户券被记为平台补贴成本。 | 冲正或补记，保留原错误事实。 |
| 储值代金券误当普通券 | 用户预付余额未冲减负债。 | 高风险差错，需财务和资金侧修正。 |
| 授权拒绝后券被核销 | 授权未成功，但营销系统扣券。 | 营销释放或补偿，资金底座不补造交易。 |

## 11. 投影和展示口径

### 11.1 用户视角

用户账单应能看懂：

| 展示项 | 说明 |
| --- | --- |
| 订单金额 | 原价或订单总额。 |
| 优惠抵扣 | 商户优惠、平台券、代金券分别展示。 |
| 实付金额 | 用户真实扣减金额。 |
| 退款金额 | 现金退款金额。 |
| 权益退回状态 | 已返券、已作废、不退、占用释放中。 |
| 不退说明 | 若权益不退，需要展示规则来源或业务说明。 |

### 11.2 商户视角

商户账单应能看懂：

| 展示项 | 说明 |
| --- | --- |
| 订单原价 | 业务成交基础价格。 |
| 商户优惠 | 商户承担的让利。 |
| 平台补贴 | 平台补足给商户的金额。 |
| 代金券结算 | 是否由平台、用户预付余额或合作方补足。 |
| 商户应收 | 清结算前的毛额。 |
| 手续费和扣减 | 平台手续费、风控扣减、追偿等。 |
| 待清算 / 可结算 | 资金在商户侧的当前状态。 |
| 退款和补贴冲回 | 退款后哪些金额被冲回或保留。 |

### 11.3 运营和财务视角

运营和财务必须能查询：

1. 某笔交易的所有权益组件、规则版本、权益引用、核销或占用凭证。
2. 用户实付、商户让利、平台补贴、代金券核销、手续费、成本的拆分。
3. 退款时每个组件的可退、已退、不可退、冲回、保留金额。
4. 营销权益系统、订单系统、资金账本和清结算之间的差异原因。
5. 人工处理、审批、凭证、操作者和处理结果。

## 12. 完整实际场景矩阵

### 12.1 正向支付场景

| 编号 | 场景 | 示例 | 资金语义 | 验收重点 |
| --- | --- | --- | --- | --- |
| S01 | 无优惠直接支付 | 订单 100，用户付 100，手续费 2。 | 用户 -100，商户 CLEARING +98，平台 FEE +2。 | 基线场景，验证不受权益设计影响。 |
| S02 | 商户优惠券支付 | 订单 100，商户券 20，用户付 80，手续费 2。 | 用户 -80，商户 CLEARING +78，平台 FEE +2，商户让利 20 不入账。 | 商户应收按优惠后计算。 |
| S03 | 平台补贴券补足商户 | 订单 100，平台券 20，用户付 80，手续费 2。 | 用户 -80，平台补贴 -20，商户 CLEARING +98，平台 FEE +2。 | 补贴资金路径和成本拆分。 |
| S04 | 平台券不补足商户 | 订单 100，平台券 20，用户付 80，商户按 80 收。 | 用户 -80，商户 CLEARING 按 80 减费入账。 | 合同口径明确，不误记补贴。 |
| S05 | 普通代金券作为平台补贴 | 订单 100，代金券 20，用户付 80。 | 按平台补贴处理。 | 代金券属性确认。 |
| S06 | 储值 / 礼品卡代金券 | 订单 100，储值券 20，用户现金付 80。 | 用户现金 -80，预付负债 -20，商户 CLEARING 按 100 减费入账。 | 不能当普通优惠券。 |
| S07 | 商户券 + 平台券叠加 | 订单 100，商户券 10，平台券 20，用户付 70。 | 商户让利 10 不入账，平台补贴 20 入账，用户 -70。 | 叠加结果由业务侧给出，资金侧只承接。 |
| S08 | 券覆盖全部金额 | 订单 100，平台券或储值券 100，用户付 0。 | 用户现金不扣；按券属性生成补贴或负债冲减。 | 零实付但有资金影响，不得因 userPay=0 拒绝整个业务事实。 |
| S09 | 优惠金额超过订单 | 订单 100，权益 120。 | 业务侧应裁剪到可用 100 或失败。 | 资金底座不得产生负实付或超额补贴。 |
| S10 | 多币种订单使用券 | USD 订单使用 USD 券或已决策 FX 快照。 | 资金底座只承接已决策币种和汇率快照。 | 不在资金底座临时换汇算券。 |

### 12.2 授权场景

| 编号 | 场景 | 示例 | 资金语义 | 验收重点 |
| --- | --- | --- | --- | --- |
| S11 | 授权时占券，完成时核销 | 订单预授权 100，券 20，现金授权 80。 | 现金 AUTHORIZATION 80，权益 HOLD 20；settle 时核销。 | 推荐模式。 |
| S12 | 授权撤销释放券 | 授权成功后用户取消。 | AUTHORIZATION -> AVAILABLE，权益 HOLD 释放。 | 不核销、不入商户 CLEARING。 |
| S13 | 授权过期释放券 | 授权未完成到期。 | 剩余 AUTHORIZATION 释放，权益 HOLD 释放或按过期规则处理。 | EXPIRE 和 REVERSAL 区分。 |
| S14 | 授权部分完成 | 授权 100，实际完成 60，券按比例或商品行核销。 | 只核销完成部分权益，释放剩余占用。 | 剩余可结算和权益剩余一致。 |
| S15 | 授权即核销不退券 | 授权成功即券作废。 | 特殊高风险模式。 | 必须有用户提示、规则快照和人工确认。 |
| S16 | 授权拒绝 | 余额不足、风控拒绝或券不可用。 | 不生成 route、posting、entry，不核销券。 | 红线场景。 |
| S17 | 强制完成含权益 | 外部已完成但内部无授权占用。 | 需要外部原事实和权益快照，不能补造授权。 | 高风险，需审计和凭证。 |

### 12.3 退款和撤销场景

| 编号 | 场景 | 示例 | 用户侧 | 资金侧 | 验收重点 |
| --- | --- | --- | --- | --- | --- |
| S18 | 无优惠全额退款 | 原付 100。 | 退现金 100。 | 按原路径冲回商户和费用。 | 基线退款。 |
| S19 | 商户券全额退款且返券 | 原价 100，商户券 20，实付 80。 | 退现金 80，返券 20。 | 商户 CLEARING 冲回优惠后金额。 | 商户让利无独立资金返还。 |
| S20 | 商户券全额退款且不退券 | 同上。 | 退现金 80，不返券。 | 商户 CLEARING 冲回优惠后金额。 | 不退券只影响用户权益。 |
| S21 | 平台补贴券全额退款且返券冲补贴 | 原价 100，平台补贴 20，实付 80。 | 退现金 80，返券。 | 平台补贴冲回，商户应收冲回。 | 用户侧和资金侧都回退。 |
| S22 | 平台补贴券不退但冲补贴 | 同上。 | 退现金 80，不返券。 | 平台补贴冲回。 | 常见“不退券但资金冲回”。 |
| S23 | 平台补贴券不退且不冲补贴 | 同上。 | 退现金 80，不返券。 | 补贴保留或成本确认。 | 必须财务和合同确认。 |
| S24 | 储值代金券退款返还余额 | 储值券 20，现金 80。 | 退现金 80，恢复储值 20。 | 恢复负债或权益余额。 | 不能误作平台补贴。 |
| S25 | 储值代金券不退 | 同上。 | 只退现金或不退券。 | 负债释放或损益口径待确认。 | 高风险专业确认。 |
| S26 | 部分退款按商品行 | 退使用了券的商品行。 | 按商品行退现金和权益。 | 按商品行冲回商户应收和补贴。 | 订单侧必须给商品行分摊快照。 |
| S27 | 部分退款按比例 | 退 40%。 | 现金、券、补贴按比例处理。 | 分摊冲回并处理尾差。 | 多次退款累计不得超额。 |
| S28 | 先退现金 | 原实付 80，权益 20，部分退 30。 | 现金先退 30。 | 权益暂不处理或最后处理。 | 用户体验好，但资金承担需确认。 |
| S29 | 权益优先不可退 | 部分退款先确认不退券。 | 可能少退现金。 | 权益不可退金额进入展示和审计。 | 前台说明和客服口径。 |
| S30 | 退款超额 | 多次退款超过可退。 | 拒绝或人工。 | 不得生成超额 entry。 | 幂等和累计控制。 |

### 12.4 清结算和对账场景

| 编号 | 场景 | 示例 | 产品处理 | 验收重点 |
| --- | --- | --- | --- | --- |
| S31 | 含商户券交易进入清分 | 商户待清算按优惠后金额。 | 清分明细展示商户让利。 | 不把商户让利记平台补贴。 |
| S32 | 含平台补贴交易进入清分 | 商户应收包含平台补贴。 | 清分金额项拆出用户实付和平台补贴。 | 补贴可核对。 |
| S33 | 含储值券交易进入清分 | 商户应收包含储值券核销。 | 清分金额项拆出负债冲减。 | 负债和商户清算一致。 |
| S34 | 清分前退款 | 交易已退款。 | 不进入清分或按剩余金额进入。 | 避免已退金额清分。 |
| S35 | 清分后清算前退款 | 清分批次已确认。 | 阻断清算候选或调整剩余可清算金额。 | 不回滚已确认清分。 |
| S36 | 清算后退款 | 商户 CLEARING 已转 AVAILABLE。 | 进入追偿、后续抵扣或负余额规则。 | 不删除历史清算。 |
| S37 | 出款后退款 | 商户已收到款。 | 生成追偿单或后续结算扣减。 | 历史出款不可回滚。 |
| S38 | 营销核销和资金入账不一致 | 营销核销 20，资金补贴 10。 | 生成对账差错。 | 不静默补平。 |
| S39 | 不退券引发客服争议 | 用户认为应返券。 | 查询原快照、规则版本和用户提示。 | 可解释可审计。 |
| S40 | 活动预算不足但资金已补贴 | 营销预算扣减失败。 | 差错单，明确责任方。 | 资金事实不可被营销失败直接覆盖。 |

### 12.5 异常和人工处理场景

| 编号 | 场景 | 产品处理 | 验收重点 |
| --- | --- | --- | --- |
| S41 | 原交易缺权益快照 | 退款或清结算无法判断。 | 进入人工处理，不按当前规则重算。 | 防止规则漂移。 |
| S42 | 权益系统超时 | 正向支付无法确认券占用或核销。 | 支付失败、待确认或业务重试，不生成不完整资金事实。 | 一致性优先。 |
| S43 | 资金成功但权益核销失败 | 资金已入账，营销未核销。 | 进入差错和补偿流程。 | 不删除资金事实。 |
| S44 | 权益核销成功但资金失败 | 营销已扣券，资金未成功。 | 释放或补偿权益，不补造资金成功。 | 防止虚假入账。 |
| S45 | 重复退款请求 | 同一退款流水重复。 | 幂等返回原结果。 | 不重复退券、不重复冲补贴。 |
| S46 | 不同退款流水累计超额 | 多次退款超过原可退。 | 拒绝或人工处理。 | 累计可退控制。 |
| S47 | 权益规则版本已下线 | 当前查不到活动规则。 | 使用原快照展示和处理。 | 快照完整性。 |
| S48 | 人工改券 | 运营人工补券或作废。 | 只影响营销系统；资金如需变化必须走差错或调账。 | 不允许后台直接改账。 |
| S49 | 税费和优惠顺序争议 | 税前优惠或税后优惠。 | 订单和财务确认，资金侧承接结果。 | 资金底座不算税。 |
| S50 | 跨主体合作方补贴 | 第三方品牌补贴商户。 | 需要合作方应收应付或平台代垫口径。 | 不能默认平台承担。 |

### 13.2 对 DSL 设计的影响

| 影响域 | 建议改动 |
| --- | --- |
| FundsInstruction | 接收业务侧已决策的权益金额组件和权益快照。 |
| AmountSpec / AmountComponent | 增加商户让利、平台补贴、代金券核销、不可退权益、补贴冲回等组件类型。 |
| RouteSnapshot | 固化权益组件、承担方、受益方、规则版本、退款处置和核销或占用引用。 |

### 13.3 对系统分析设计的影响

| 模块 | 影响点 |
| --- | --- |
| wallet-face / transaction-face | 请求模型需要表达权益金额组件和快照引用，且保持幂等摘要包含权益快照。 |
| transaction-impl | 交易编排保存权益快照，路由和账务计划按组件拆分。 |
| ledger-impl | 账本只接收资金语义明确的 posting，不解释营销规则。 |
| reconciliation-* | 对账对象增加营销权益系统和权益差错。 |
| projection | 用户、商户、运营、财务投影增加权益拆分和不退券展示。 |
| ops / governance | 人工处理必须通过差错、调账、补偿或审计流程，不允许直接改账。 |

### 13.4 对 TDD 设计的影响

| 测试类型 | 新增重点 |
| --- | --- |
| 直接交易流程测试 | 商户券、平台补贴券、储值代金券、零实付、叠加券。 |
| 授权流程测试 | 授权占券、释放券、部分完成核销、授权拒绝不扣券。 |
| 退款测试 | 不退券、返券、冲补贴、不冲补贴、部分退款分摊、退款超额。 |
| 清结算测试 | 含权益交易清分、补贴冲回、已清算后退款、出款后追偿。 |
| 对账差错测试 | 营销核销和资金入账不一致、缺快照、储值券误分类。 |
| 红线测试 | 资金底座不得重新计算券、不得授权拒绝后入账或核销、不得把储值券当普通券。 |

### 13.5 对 OpenSpec 和编码批次的影响

| 影响项 | 建议 |
| --- | --- |
| 公共契约 | 需要 Execution Grant 明确是否允许新增枚举、请求字段、DTO、快照字段。 |
| 枚举 | 组件类型、退款处置、资金性质、权益状态引用可能新增。 |
| 表结构 | 如果快照持久化字段不足，需要单独授权修改表结构或扩展 JSON 快照。 |
| 编码顺序 | 建议先产品和 DSL 冻结，再系分和 TDD，最后进入交易主链路实现。 |
| 兼容性 | 历史无权益快照交易按“无权益组件”处理；缺快照的权益交易进入人工处理，不回填臆造规则。 |

## 14. 产品验收标准

| 验收点 | 通过标准 |
| --- | --- |
| 职责边界 | 资金底座不计算优惠券，只承接权益结果快照。 |
| 金额闭合 | 订单原始金额、用户实付、商户让利、平台补贴、代金券核销合计可解释。 |
| 资金路径 | 每个有资金影响的权益组件都有承担方、受益方、账务路径或明确无账口径。 |
| 快照完整 | 后续退款、撤销、授权过期、清结算和对账不依赖当前营销规则。 |
| 不退券可解释 | 用户侧不退券和资金侧不冲补贴分离表达。 |
| 授权安全 | 授权拒绝不生成 route、posting、entry，也不核销券。 |
| 清结算拆分 | 商户让利、平台补贴、代金券核销、手续费、补贴冲回可拆分。 |
| 对账闭环 | 订单、营销、资金、账本、清结算差异能定位到具体组件。 |
| 人工处理 | 缺快照、规则冲突、核销差异进入差错或人工处理，不静默重算。 |

## 15. 待确认项

| 编号 | 待确认项 | 影响 |
| --- | --- | --- |
| C01 | 当前业务是否存在储值、预付、礼品卡型代金券。 | 决定是否需要负债或预收待付账户建模。 |
| C02 | 平台补贴券是否一定补足商户，还是存在商户按优惠后金额结算。 | 决定平台补贴是否生成资金路径。 |
| C03 | 不退券时，平台补贴是否冲回。 | 决定退款账务和清结算金额项。 |
| C04 | 部分退款默认按商品行、比例、现金优先还是权益优先。 | 决定退款计算和测试矩阵。 |
| C05 | 授权交易是否允许授权成功即核销不可退券。 | 决定授权风险边界和用户提示。 |
| C06 | 手续费基数按订单原价、用户实付、商户应收还是合同口径。 | 决定费用组件和清结算结果。 |
| C07 | 优惠券过期、不退、作废、沉淀是否涉及财务收入或负债释放。 | 需要财务、会计、合规确认。 |
| C08 | 是否存在第三方合作方补贴。 | 决定补贴承担方是否只是平台。 |
| C09 | 历史交易缺权益快照时如何迁移或处理。 | 决定兼容策略和人工处理范围。 |
| C10 | 对用户展示“不退券”的时点和话术由哪个系统负责。 | 决定客服争议和产品体验。 |

## 16. 建议落地顺序

| 阶段 | 目标 | 产物 |
| --- | --- | --- |
| 阶段 1：产品确认 | 确认职责边界、权益分类、退款处置、实际场景和待确认项。 | 本文评审通过或修订。 |
| 阶段 2：合入现有设计 | 把确认内容合入 PRD、DSL、系分、TDD 和 OpenSpec。 | 权威设计更新和影响说明。 |
| 阶段 3：TDD 拆解 | 按 S01-S50 场景拆测试矩阵和红线用例。 | TDD 场景、验收断言、失败用例。 |
| 阶段 4：契约和实现授权 | Execution Grant 明确公共契约、枚举、表结构和实现范围。 | 编码批次授权。 |
| 阶段 5：分批编码 | 先普通商户券和平台补贴券，再处理储值代金券和复杂授权模式。 | 小批次实现、验证和回归。 |

推荐一期范围：

1. 支持商户优惠券、平台补贴券、普通代金券按平台补贴处理。
2. 支持权益快照、组件级退款处置、不退券和补贴冲回。
3. 授权场景采用“授权时占用权益，完成时核销权益”的推荐模式。
4. 储值、预付、礼品卡型代金券先作为待确认专项，不混入普通优惠券实现。
