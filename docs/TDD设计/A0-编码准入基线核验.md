# A0 编码准入基线核验

## 1. 文档定位

A0 是进入编码前的只读核验页，用于把 PRD、DSL、系分、TDD、OpenSpec、当前代码、测试资产、H2 schema 和验证环境对齐成同一条准入基线。A0 只输出差距、首批 Red 候选、写入范围建议、禁止范围和停止条件，不授权修改生产代码、测试代码、DDL/H2 schema 或运行时配置。

A0 的结论只能作为下一步 Execution Grant 的输入，不能作为 Done 证据。若后续任务要进入编码，必须由用户确认单一 MVP 任务切片，并明确 `writeScope`、`noWriteScope`、`firstRedSet`、验证命令和 Not Done 条件。

## 8. nextExecutionGrantRequest

推荐首个编码授权从 A1 直接交易事实红线开始，因为它最能用最小范围证明资金底座核心不变量：交易事实、路由快照、posting plan、ledger entry、余额投影、幂等和失败无副作用。若业务优先级明确要求授权或余额控制，也可以改为 A2 或 A3，但不能混合授权。

建议授权字段如下：

| 字段 | 建议取值 |
| --- | --- |
| `abilityBatch` | A1 直接交易事实红线。 |
| `businessQuestion` | 一笔直接交易成功或失败后，使用者、运营、财务和研发是否能通过统一资金事实解释状态、金额、账目、余额和审计证据。 |
| `writeScope` | 先允许写目标测试资产；Red 证明真实缺口后，才在 `transaction-impl`、`ledger-impl`、必要的 face/core 契约范围内做最小修复。是否允许公共契约、状态机、表结构、H2 schema 变更必须单独写明。 |
| `noWriteScope` | B7 清结算与对账、B8 资金数据治理、P2 业务能力包、外部协议、生产运行配置、未授权 DDL/H2 schema、历史事实修复和敏感数据处理。 |
| `firstRedSet` | 优先 `A1-RED-001`；若目标是失败路径，则选 `A1-RED-002`。 |
| `minimumAssertions` | 状态、DSL 借贷表命中行、账户类型、`normalBalanceSide`、余额桶、route snapshot、posting plan、ledger transaction、ledger entry、projection、借贷平衡、余额影响、幂等、审计和 forbidden facts。 |
| `verificationAndStop` | 先运行对应 `just test-one`；修复后运行相关 `just test-transaction`、`just test-business-flow`、`just test-boundary`；触碰代码时补 `just compile` 和 `just pmd`。遇到公共契约、表结构、外部规则、B7/B8/P2 或敏感数据边界立即停止并回到授权。 |
