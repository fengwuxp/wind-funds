| --- | --- |
| `mvpScenario` | A1 直接交易事实红线：一笔直接交易成功或失败后，使用者、运营、财务和研发都能通过统一资金事实解释状态、金额、账目、余额和审计证据。 |
| `abilityBatch` | A1 / B3 覆盖索引中的 P1 直接交易入口；本轮只选择直接交易事实红线，不混入 A2 授权交易、A3 余额控制、A4 DSL 执行化、B7 清结算对账、B8 归档治理或 P2 业务能力包。 |
| `businessQuestion` | 用户支付、充值、转账、退款或提现确认后，系统是否同时证明交易事实、route snapshot、posting plan、ledger transaction、ledger entry、余额投影、幂等和失败无副作用。 |
| `moneyFact` | 已确认发生的直接交易资金事实进入资金底座，生成资金交易、交易明细、route snapshot、posting plan、账本交易、分录引用和余额投影。 |

| `productNotDone` | 不声明完整清结算、对账、归档治理、P2 业务生产流、外部通道规则确认、FX 执行、出款生命周期或含权益生产资金流闭合。 |
| `firstRedSet` | 优先 `A1-RED-001` 成功链路事实完整性；随后 `A1-RED-002` 失败无副作用和幂等冲突。 |

## 9. stopConditions

1. 需要修改 face/core 公共契约、枚举、状态机、Request/DTO 或 DSL 字段但本页未授权。
2. 需要新增或修改生产表结构、H2 schema、唯一键、索引、Entity 或 Mapper。
3. 直接交易 Red 触碰清结算、对账、出款、归档、治理、指标、VCC、全球账户、ACH、银行转账或收单专项。
4. 涉及税务、会计、合同、卡组织、银行、通道、KYC/KYB/AML、客户资金、跨境、FX 或外部规则核验状态，且无法证明只做本地直接交易边界。
5. 测试无法表达余额桶、posting plan、ledger entry、projection、幂等或失败无副作用，只能断言状态或数量。
6. 工作树出现未分类变更，或用户未提交变更与本任务写入范围冲突。
