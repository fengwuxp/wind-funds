# 支付资金底座系分设计

## 目录定位

本目录是支付资金底座的系统分析设计入口。完整设计包入口见 [../README.md](../README.md)。它承接产品设计和 DSL 设计，把产品目标、资金概念、业务流程、验收红线转成可编码、可测试、可观测、可审计的系统设计。

本目录只描述目标系统设计、职责边界和编码准入约束。

业务接入方需要确认服务入口、写入范围、只读范围、验证命令和 Execution Grant 材料时，先读 [../用户接入指南/README.md](../用户接入指南/README.md)。用户接入指南只做接入翻译和准入检查，系统职责和编码边界仍以本目录为准。

## 系统落地优先级

系分设计承接产品侧能力保障顺序，所有编码批次、Execution Grant 和测试门禁先按资金底座不变量判断优先级。

| 顺序 | 能力范围 | 系分落地要求 |
| --- | --- | --- |
| P0 | 钱包、账本、账目、余额投影、对账、清分、清算、结算、大数据归档、账本余额快照。 | 先稳定可记账主体、账目 bucket、账本周期、ledger entry、余额投影、对账差错、清分清算对象、结算单、归档 Manifest、checkpoint、watermark、差异报告和账本余额快照。 |
| P1 | 直接交易、授权交易、余额控制、交易投影。 | 在 P0 的账户、账本、账目和运营账务闭环之上落资金动作入口、幂等、生命周期、route snapshot、冻结/解冻/调整和只读交易视图。 |
| P2 | VCC 发卡业务、全球账户收付款、收单业务支持。 | 通过场景交易 capability pack 适配外部业务事实，不新增平行钱包、平行账本、平行清结算、平行对账或平行归档链路。 |

如果同一批次同时触碰多个层级，必须优先证明 P0 能力没有被破坏，再证明 P1 交易入口正确，最后证明 P2 业务语义适配正确。

| 结构项 | 本目录回答 | 权威落点 |
| --- | --- | --- |
| 需求背景和问题 | 支付资金底座要解决资金事实、账户、路由、账务、投影、对账清结算、归档治理的系统承接问题；不做的风险是业务能力各自复制钱包、账本、清结算和归档链路。 | 01-系分设计总览、03、04、05。 |
| 目标、非目标和边界 | 目标是形成可编码、可测试、可观测、可审计的统一资金系统；非目标是不替代上层业务审批、外部协议全集、风控模型、合规最终判断和报表指标实现；系统边界、数据边界和安全边界分别落在 face/core 契约、账本事实源和权限审计红线。 | 本 README 的系统落地优先级、系分准入评估口径、实现承接清单，以及 01、05。 |

## 系分准入评估口径

系分设计的准入目标是证明产品和 DSL 已经能落到可编码、可测试、可观测、可审计的系统边界。完整跨文档门禁见 [../README.md#设计准入评估总控](../README.md#设计准入评估总控)。

| 评估维度 | 系分侧必须证明 | 阻断信号 |
| --- | --- | --- |
| 可用性 | 每个业务能力有服务入口、状态机、失败路径、人工处理入口和只读查询口径。 | 只有流程图，没有接口、状态、表或失败处理落点。 |
| 资金安全 | 事务边界、唯一约束、幂等键、余额桶、账本周期、分录平衡、快照回放和失败无副作用均可落地。 | 失败路径会产生半截 route、posting、entry 或投影；错账只能人工改库。 |
| 金融红线 | 权限、审批、审计、敏感字段、导出、外部协议、规则版本和待确认项有系统承接。 | 高危操作无审批审计；敏感信息进入普通日志、快照、导出或报表。 |
| 易用性 | 用户账单、商户账单、运营时间线、差错处理台、告警和错误原因能解释资金状态。 | 查询视图无法区分授权、冻结、清算、结算、争议、退款和退汇。 |
| 可理解性 | 模块边界、依赖方向、状态和数据对象承接产品/DSL 术语。 | 钱包、交易、路由、账本、清结算、归档或指标职责交叉写入事实。 |
| 可开发性 | Request/Query/DTO、表结构、索引、状态迁移、事务、重试、补偿、观测和生产安全口径明确。 | 实现时还需要临时决定公共契约、核心表结构或跨模块依赖方向。 |
| 可测试性 | 每个服务入口能映射到 TDD 用例、数据准备、断言事实、观测指标和红线失败。 | 只描述实现步骤，无法证明余额、分录、投影、审计和无副作用。 |

## 实现承接清单

进入任一编码批次前，研发需要把本清单落到任务说明或 Execution Grant。缺项时，系分视为带条件通过，不得直接开工。

| 承接项 | 必须明确 | 证据入口 |
| --- | --- | --- |
| 服务契约 | 本批次新增或修改的 face 接口、Request、Query、DTO、枚举和错误码；未允许触碰公共契约时只能在 impl 内闭合。 | 对应系分分册服务契约章节、OpenSpec 批次授权。 |
| 状态机 | 对象状态、合法迁移、失败终态、人工终态、幂等重复处理和并发冲突结果。 | 产品验收矩阵、系分状态机、TDD 正反向用例。 |
| 表和索引 | 表职责、唯一键、幂等键、查询索引、审计字段、摘要字段和不可变字段；若本批次涉及 03、04 分册新表，必须声明是否允许同步新增 DDL 和 H2 schema。 | 系分表设计章节、tests/src/test/resources/jdbc-schema.sql、DDL 影响说明。 |
| H2 schema 准入 | 编码批次触碰数据库、Mapper、Entity、查询或状态持久化时，必须同步维护 tests/src/test/resources/jdbc-schema.sql 或说明只读不落库；清结算、归档、重放和治理表未进入 schema 前，不得宣称对应能力已具备数据库级验证。 | DDL 影响说明、H2 测试、Execution Grant 写入范围。 |
| 架构边界测试 | 本批次是否新增或复用 LayerBoundaryTests，以及如何证明 face 模块不依赖 impl 模块、生产模块不依赖 tests、wallet 不写交易事实、route 不写账本事实、ledger 不持有业务交易生命周期。 | TDD L5、模块依赖检查、边界测试类、just test-boundary。 |
| 事务和补偿 | 同事务内完成什么，外部调用和批量扫描不放入什么事务，失败后如何补偿或重试。 | 系分一致性章节、TDD 幂等和失败无副作用用例。 |
| 观测和审计 | 指标、日志、traceId、审批号、凭证、告警、差异报告和人工处理入口。 | 系分 05、各分册非功能设计、TDD 运营权限和红线用例。 |
| 外部边界 | 通道、银行、卡组织、FX、报表指标、合规/会计/税务未确认部分是否排除在本批次外。 | 产品待确认项、docs 总入口批次准入卡。 |

### 生产可用性和安全承接卡

编码批次若触碰资金写入、清结算、对账、归档、重放、敏感查询、导出或高危运营操作，系分必须额外补齐下列承接项。缺项时，即使功能流程清楚，也只能视为设计带条件通过。

| 承接项 | 必须明确 | 不满足时的风险 |
| --- | --- | --- |
| 可用性目标 | 核心接口或任务的成功口径、失败口径、超时、重试、幂等和人工兜底。 | 失败后只能靠人工查库或反复重试，放大资金副作用。 |
| 资金安全控制 | 余额桶、账本周期、唯一键、幂等键、锁、审批、凭证和账务平衡校验。 | 重复入账、超额释放、跨主体误调账、出款重复或半截入账。 |
| 金融红线控制 | 法域、资质、外部规则、客户资金、商户待结算资金、KYC/KYB/AML、敏感数据和导出边界。 | 把内部核算误写成持牌清算结论，或让未确认规则进入默认放行路径。 |
| 易用性输出 | 查询 DTO、交易投影、运营时间线、错误原因、告警文案和人工处理入口。 | 系统内部正确但使用者无法判断下一步动作。 |
| 可理解性约束 | 服务、表、状态、枚举和错误码命名承接 PRD/DSL 术语，避免同词异义。 | 实现时把授权完成、商户结算、账本周期、清算账期和指标水位混用。 |
| Runbook 触发 | 哪些失败、积压、差异或告警需要暂停任务、人工复核、补偿、重放或回滚。 | 告警没有负责人、阈值和动作，不具备生产处理能力。 |

### 独立 Execution Grant 防混入门禁

交易主链路批次可以读取清结算、对账、归档和治理设计，但不得顺手新增相关生产写入、表结构、服务入口或调度能力。下列能力域必须独立授权，避免把目标态设计混入 P1 交易主线。

| 能力域 | 可以在交易主线批次做什么 | 必须独立授权后才能做什么 | 独立授权必填 | 首批 Red |
| --- | --- | --- | --- | --- |
| 清结算与对账 | 只读复核 PRD/DSL/系分/TDD，确认交易事实能提供清结算和对账所需来源引用。 | 新增或修改对账任务、匹配结果、差错单、清分明细、清分批次、清算候选、清算批次、结算单、出款单、追偿单、运营补事实命令、DDL/H2、Entity、Mapper、服务 API 或调度任务。 | 独立 OpenSpec change、Execution Grant、`CLS-GATE-*`、写入范围、DDL/H2 范围、外部规则核验、运营补事实白名单、权限审计、并发重跑和 Not Done。 | `TDD-B7-RED-001` 至 `TDD-B7-RED-007`。 |
| 归档重放与治理 | 只读复核交易和账本事实是否具备归档、重放和差异报告所需不可变引用。 | 新增或修改 governance 物理模块、归档申请、Manifest、checkpoint、watermark、重放任务、差异报告、人工处理入口、治理导出、指标水位控制、DDL/H2、Entity、Mapper、服务 API 或任务调度。 | 独立 Execution Grant、`GOV-GATE-*`、物理落点、只读边界、范围锁、dry-run/apply、回滚/续跑、指标水位隔离、边界测试和 Not Done。 | `TDD-B8-RED-001` 至 `TDD-B8-RED-005`。 |
| P2 业务能力包 | 只读复核 VCC、全球账户、ACH 或收单业务对统一交易、钱包、账本、账目、清结算、对账和归档的要求。 | 新增业务场景交易入口、外部状态映射、业务专项 DTO、外部引用脱敏、业务回归矩阵或规则待确认流程。 | 对应业务 PRD、能力边界、外部规则状态、敏感数据边界、P0/P1 回归范围和不新增平行内核承诺。 | 业务状态映射、乱序重复、脱敏、规则待确认和 P0/P1 回归 Red。 |

如果 A0-A4 交易主线批次发现必须修改 B7/B8 或 P2 才能继续，当前批次应停止在差距复核结论，不得扩大写入范围；由新的 Execution Grant 重新声明目标、写入范围、首批 Red、验证命令和停止条件。

### A0 系分基线核验清单

A0 系分核验用于确认目标能力是否已经具备可编码边界，但不直接开工。A0 输出的是模块差距、契约差距、DDL/H2 差距、测试差距和扩权建议；未获得 Execution Grant 前，不得把系分目标态设计转成生产代码、测试代码、表结构或配置写入。

| 核验面 | 必须确认 | 准入动作 |
| --- | --- | --- |
| 模块边界 | 本批能力落在哪个 face/core/impl/tests 模块，是否会跨 wallet、transaction、route、ledger、reconciliation 或 governance 写事实。 | 未跨域时进入范围锁定；跨域时写清只读范围和独立授权需求。 |
| 公共契约 | 是否新增或修改 face 接口、Request、Query、DTO、枚举、错误码或 core 值对象。 | 未授权时只能在既有契约内闭合；需要变更时先扩 Execution Grant。 |
| 数据落点 | 是否新增或修改表、索引、唯一键、状态字段、Entity、Mapper、DDL 或 H2 schema。 | 触碰持久化时必须同步 DDL/H2 写入范围和服务级 H2 测试。 |
| 状态机 | 初始状态、成功终态、失败终态、人工终态、并发冲突和幂等重复结果是否明确。 | 状态不清时先补系分状态机和 TDD Red。 |
| 事务和幂等 | route、posting、entry、projection、批处理和重放的事务边界、唯一约束、锁和补偿策略明确。 | 缺失败无副作用或并发处理时阻断编码。 |
| 观测审计 | traceId、业务引用、审批号、凭证摘要、差异报告、告警、人工入口和敏感脱敏有落点。 | 涉及真实资金、高危操作、导出或出款时缺失即阻断。 |
| 独立能力域 | 是否触碰清结算/对账 B7、归档/治理 B8、P2 业务能力包或外部轨道规则。 | 命中时切独立 Execution Grant；A0-A4 不混入写入。 |

## 核心系统结论

1. 写入链路必须从资金事实进入交易或余额控制契约，再经过路由、账务计划、账本过账和投影派生。
2. 钱包账户只管理主体、工具、账本初始化和余额查询，不直接表达资金交易成功。
3. 路由只解析参与方、账户、账目、周期和快照，不写交易事实或账本事实。
4. 账本分录是余额事实源；余额投影、余额变更日志、交易投影和指标都是只读派生。
5. 对账清算模块统一承载对账、清分、清算、结算、出款、差错和追偿，但对账批次、匹配结果、差错单、可清分明细、清分批次、清算候选、清算批次、结算单、出款单和追偿单必须分别建模；对账任务、匹配结果和差错闭环是清分、清算、结算、出款和追偿的基础准入能力。
6. 资金数据治理逻辑能力 governance 只负责资金事实、投影、归档、重放、差异和生产修复证据链治理；归档只改变冷热位置，不改变事实身份；重放只修复读模型或投影，不重新入账；异常人工处理只能审批、补证据、调整范围、重跑或关闭差异；指标项只作为报表指标模块输入边界。
7. 所有资金变化必须能被测试同时证明：状态、金额、账目、账本、投影、幂等、审计和异常路径。

## 术语落地约定

授权交易分册中保留的“授权结算”“部分结算”“已结算金额”等表达，是对产品侧业务语言的承接。进入接口、事件、表字段、测试命名和状态机时，优先使用“授权完成”“部分完成”“已完成金额”和 AUTHORIZATION_TRANSACTION / SETTLE。商户清结算分册中的“结算锁定”和 SETTLEMENT 账目只表示出款前锁定金额，不表示授权完成事件。
