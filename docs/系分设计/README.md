# 支付资金底座系分设计

## 目录定位

本目录是支付资金底座的最终版系统分析设计入口。完整设计包入口见 [../README.md](../README.md)。它承接产品设计和 DSL 设计，把产品目标、资金概念、业务流程、验收红线转成可编码、可测试、可观测、可审计的系统设计。

本目录只描述最终态系统设计。

## 系分模板约定

核心业务分册遵循“文档定位、需求背景、目标、概要设计、详细设计、非功能设计、实施切片与准入门禁、参考资料”的结构。`05` 是横切专项，服务于所有模块的测试、观测、安全和金融红线，不重复承载业务表设计。

表设计落点：

| 分册 | 表设计章节 |
| --- | --- |
| `01` | 数据表分册总览和通用约束。 |
| `02` | 主链路、账户、账本、余额投影、余额日志和交易投影表。 |
| `03` | 清算候选、清算批次、结算单、出款单、对账、差错、追偿和审计表。 |
| `04` | 归档申请、Manifest、检查点、水位、重放任务和差异报告；指标只列产品和业务关心的指标项，不设计指标表。 |

## 统一边界

| 层级 | 职责 | 禁止 |
| --- | --- | --- |
| `core` | 资金 DSL、枚举、值对象、路由、账本端口和共享契约。 | 依赖 DAL、Web、消息、具体实现或测试模块。 |
| `wallet-face` | 钱包账户、信用账户、预算组、支付工具、主体余额查询契约。 | 暴露 Entity、Mapper 或交易实现细节。 |
| `wallet-impl` | 钱包账户建模、支付工具绑定、显式账本初始化和余额查询实现。 | 直接写交易事实、账本事实或在交易路径自动建账。 |
| `transaction-face` | 直接交易、授权交易、余额控制、生命周期和查询契约。 | 暴露 DAL 实现或承载账本落地细节。 |
| `transaction-impl` | 资金指令转换、路由解析、快照保存、生命周期记录和交易编排。 | 直接修改余额投影或绕过账本写分录。 |
| `ledger-face` | 账本、账本交易、分录查询和账本写入契约。 | 承载业务订单、清结算单据或交易生命周期状态。 |
| `ledger-impl` | 账本、账务计划、分录、余额投影和余额变更事件实现。 | 重新路由、处理业务订单或把投影视为事实源。 |
| `tests` | 契约测试、流程测试、架构边界测试和数据一致性测试。 | 被生产模块依赖。 |

## 核心系统结论

1. 写入链路必须从资金事实进入交易或余额控制契约，再经过路由、账务计划、账本过账和投影派生。
2. 钱包账户只管理主体、工具、账本初始化和余额查询，不直接表达资金交易成功。
3. 路由只解析参与方、账户、账目、周期和快照，不写交易事实或账本事实。
4. 账本分录是余额事实源；余额投影、余额变更日志、交易投影和指标都是只读派生。
5. 清算候选、清算批次、结算单、出款单、对账批次、差错单和追偿单必须分别建模。
6. 归档只改变冷热位置，不改变事实身份；重放只修复读模型或投影，不重新入账。
7. 所有资金变化必须能被测试同时证明：状态、金额、账目、账本、投影、幂等、审计和异常路径。

## 术语落地约定

授权交易分册中保留的“授权结算”“部分结算”“已结算金额”等表达，是对产品侧业务语言的承接。进入接口、事件、表字段、测试命名和状态机时，优先使用“授权完成”“部分完成”“已完成金额”和 `AUTHORIZATION_TRANSACTION / SETTLE`。商户清结算分册中的“结算锁定”和 `SETTLEMENT` 账目只表示出款前锁定金额，不表示授权完成事件。
