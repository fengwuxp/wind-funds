# 测试、观测、安全与金融红线专项设计

## 一、文档定位

本文是支付资金底座系分设计的横切专项，不是独立业务模块系分，也不承载业务表设计。业务模块的数据表、接口、状态机和流程设计分别见 02、03、04；本文把产品验收矩阵、DSL 契约和模块系分设计转成测试设计、可观测设计、安全审计和金融红线，作为开发、测试、评审和上线前检查的统一入口。

## 二、测试驱动设计总则

资金系统测试不是覆盖代码分支，而是证明资金事实可信。每个有资金影响的场景，都必须同时回答：

1. 输入事实是什么。
2. 状态如何变化。
3. 哪些主体、账目、账本周期发生余额变化。
4. route snapshot 和 posting plan 是否可追溯、可平衡。
5. ledger entry 和余额投影是否一致。
6. 幂等、异常、权限和审计是否成立。
7. 必须失败的红线是否真的失败。

```mermaid
flowchart TD
    A["产品验收场景"] --> B["定义输入事实\n主体 / 金额 / 币种 / 业务引用 / 周期"]
    B --> C["定义状态机预期"]
    C --> D["定义 route 和账目变化"]
    D --> E["定义 posting plan 和 ledger entry 断言"]
    E --> F["定义余额投影和交易投影断言"]
    F --> G["定义幂等、异常、权限、审计断言"]
    G --> H["编写 TDD 用例"]
    H --> I["回归门禁和观测指标"]
```

## 三、测试分层

| 测试类型 | 保护对象 | 真实链路要求 |
| --- | --- | --- |
| 领域单元测试 | 金额、币种、周期、状态、规则、值对象。 | 直接测试真实逻辑，替换时间和 ID。 |
| 指令转换测试 | Request 到 FundsInstructionSpec、金额快照、上下文。 | 真实转换器，不访问数据库。 |
| 路由契约测试 | RouteResolver、ResolvedRouteSpec、route snapshot。 | 真实路由逻辑，替换账户查询或使用测试 fixture。 |
| 账务组装测试 | LedgerPostingAssembler、posting plan、ledger entry spec。 | 真实 assembler，断言独立平衡。 |
| 应用流程测试 | 直接交易、授权交易、余额控制、清结算、对账差错。 | 真实内部编排，替换外部通道和不可控依赖。 |
| 数据库测试 | 唯一约束、事务、幂等、查询条件、周期 bucket。 | 使用测试库或 H2 MySQL Mode，不 mock Mapper。 |
| 契约测试 | face 接口、DTO、Query、Spec、DSL JSON 样例。 | 不依赖私有实现。 |
| 可解释性测试 | 用户账单、商户账单、运营时间线、财务对账视图、审计导出和 SRE Runbook 信号。 | 真实生成查询 DTO、投影摘要、错误原因或告警上下文，不反写资金事实。 |
| 架构边界测试 | 模块依赖、包依赖、Entity 外露、tests 依赖。 | 静态扫描或 ArchUnit。 |
| 红线失败测试 | 外部账户入账、直接改余额、缺快照逆向等。 | 必须证明失败且无副作用。 |

## 四、场景到测试矩阵

### 4.1 交易、路由、钱包、账目与投影

| 场景 | 最低测试组合 | 核心断言 |
| --- | --- | --- |
| 充值成功 | 指令转换、路由、账务、流程、数据库 | 外部账户只做引用；用户 AVAILABLE 增加；分录平衡。 |
| 商户订单收款 | 路由、账务、流程、余额断言 | 用户 AVAILABLE 减少；商户 CLEARING 增加；费用拆分。 |
| 普通转账 | 路由、账务、流程、幂等 | 付款方减少、收款方增加；币种一致；同主体失败。 |
| 授权批准 | 授权流程、账务、余额断言 | AVAILABLE -> AUTHORIZATION；保存授权快照。 |
| 授权拒绝 | 授权流程、红线 | 不生成 route、posting plan、ledger entry、chargeback。 |
| 授权撤销/结算/退款 | 原路径回放、状态机、余额断言 | 不超过剩余额度或已结算金额；缺快照失败。 |
| 授权强制完成/无授权退款 | 授权流程、策略校验、审计、余额断言 | 强制完成不伪造授权占用；无授权退款以空原授权流水进入 no-auth 语义，有 `externalReferenceSn`、退款原因、操作者和审计，不得携带或查询内部授权流水。 |
| 冻结/解冻 | 余额控制流程、冻结单状态、账务 | 只做同主体 AVAILABLE <-> FROZEN。 |
| 余额控制 adjust | 余额控制服务、资金账户、信用额度、预算控制视图、账务、审计 | 资金账户余额调整必须有来源、审批、凭证和审计；信用账户额度只影响信用账户 LIMIT / AVAILABLE；预算控制调整只更新预算控制视图、Spend Rule 快照和审计证据；缺来源、错币种、跨主体价值转移失败。 |
| 对账差错调账 | 审批、差错引用、账务、审计 | 必须经差错单、审批、凭证和重新对账；可引用 BALANCE_ADJUST 或批次授权调账事实；历史分录不变。 |
| 账本周期 | 路由、账本、余额查询 | 非 LIFETIME 缺 periodId 失败；不同周期不串账。 |
| 余额日志 | 余额投影、事件补偿 | 日志失败不回滚投影；日志不反写余额。 |
| 交易投影 | 只读投影、重放 | 投影不写事实；无范围重放失败。 |

### 4.2 清结算与对账

| 场景 | 最低测试组合 | 核心断言 |
| --- | --- | --- |
| 交易进入可清分 | 可清分规则、数据库、幂等 | 只来自成功交易、已过账商户 CLEARING 分录、完整 route snapshot、posting plan 和账本分录；生成可清分明细不改余额。 |
| 清分批次确认 | 批次状态、规则版本、审计 | 只固化明细归类、清分周期、规则版本和金额摘要，不触发 CLEARING -> AVAILABLE。 |
| 清算候选生成 | 候选规则、前置对账、数据库、幂等 | 只来自已确认清分批次；清算账期满足且清算前置对账可放行。 |
| 候选排除 | 规则、状态、审计 | 退款、争议、冻结、重大差错、风控阻断可见。 |
| 清算批次确认 | 批次状态、交易事实、账务 | 只确认一次；触发 CLEARING -> AVAILABLE。 |
| 结算单生成 | 净额计算、规则版本、审批 | 每个金额项可追溯；策略解析失败不静默实时。 |
| 结算锁定 | 交易事实、账务、幂等 | AVAILABLE -> SETTLEMENT；出款中不可再次结算。 |
| 出款成功/失败 | 出款状态、外部回单、账务 | 受理不等于成功；失败回退只一次。 |
| 对账差错 | 对账批次、差错单、调账 | 差错不直接改账；重大差错阻断；有条件放行有审批、阈值、账龄和到期重查；核销前必须重新对账。 |
| 追偿 | 追偿状态、负余额、抵扣 | 已出款后逆向不回滚历史出款。 |

### 4.3 归档、重放与指标

| 场景 | 最低测试组合 | 核心断言 |
| --- | --- | --- |
| 归档前置 | 规则、数据、权限 | 缺范围、检查点、水位、Manifest、审批必须失败。 |
| 归档后查询 | 冷热查询、审计 | 历史明细、余额和对账追溯可定位。 |
| 水位推进 | 批处理、差异报告 | 先计算、写摘要、校验，再推进。 |
| 余额重建 | 检查点、增量分录、差异报告 | 不从交易投影或报表反推余额。 |
| 交易投影重放 | 三种模式、范围、幂等 | 不重新入账，不改分录，不改余额事实。 |
| 指标项承接 | 指标项、业务问题、推荐事实来源 | 指标只读；异常不反写资金事实；不复用归档 Manifest、水位或重放 checkpoint。 |
| 敏感导出 | 权限、安全、审计 | 无审批、无脱敏、超范围必须失败。 |

### 4.4 使用者可解释性与运营可用性

| 场景 | 最低测试组合 | 核心断言 |
| --- | --- | --- |
| 用户账单解释 | 交易投影、余额桶、失败原因、权限 | 能说明扣款、冻结、授权、退款、释放或失败的来源；授权占用不展示成最终消费，冻结不展示成已扣款。 |
| 商户账单和结算解释 | 商户投影、清分/清算/结算对象、权益金额项 | 能说明待清算、可结算、结算锁定、出款中、已出款、退款、争议和追偿；重大差错或前置对账未完成时不得展示为可出款。 |
| 运营时间线 | 资金交易、route snapshot、账务结果、差错、审批和下一步动作 | 能按时间线串起事实、处理单、失败阶段和可操作入口；不得只返回技术错误码。 |
| 财务对账视图 | 对账批次、匹配结果、余额公式、差错单、调账引用 | 能解释账实、账账、单账和余额一致性；差错核销后必须能看到重新对账结果。 |
| 审计和敏感导出 | 权限、审批、脱敏、水印、下载记录 | 无权限、无审批、超范围或未脱敏导出必须失败；审计记录不能缺操作者、原因、范围和结果。 |
| SRE Runbook 信号 | 告警、trace、业务键、幂等键、任务范围、差异报告 | 告警必须能定位影响范围、止血动作、恢复动作和恢复验收；无负责人、阈值或动作的告警不算有效告警。 |

## 六、可观测设计

### 6.1 Trace 维度

所有写入链路和高危任务必须贯穿：

| 字段 | 说明 |
| --- | --- |
| traceId | 单次调用链路追踪。 |
| tenantId | 租户。 |
| businessScene/businessSn | 业务场景和业务流水。 |
| fundsTransactionSn | 资金交易流水。 |
| ledgerTransactionSn | 账本交易流水。 |
| routeSnapshotId | 路由快照引用或摘要。 |
| batchSn/taskSn | 清结算、对账、归档、重放和指标任务号。 |
| operator | 操作者和系统身份。 |

### 6.2 日志规范

| 日志类型 | 必须包含 | 禁止 |
| --- | --- | --- |
| 交易日志 | 阶段、业务流水、交易流水、状态、失败原因。 | 敏感账户、卡号、密钥、完整外部凭证。 |
| 路由日志 | 解析器、参与方摘要、账目、周期、失败原因。 | 支付工具完整号、外部账户原文。 |
| 账本日志 | 账本交易、posting 数、entry 数、平衡结果。 | 分录全量敏感上下文。 |
| 清结算日志 | 批次、金额摘要、状态、审批。 | 未脱敏导出路径。 |
| 重放日志 | 范围、模式、checkpoint、差异摘要。 | 无范围全量明细。 |
| 安全日志 | 操作者、权限、审批、资源、结果。 | 密钥、token、证件原文。 |

### 6.3 指标和告警

| 域 | 告警条件 |
| --- | --- |
| 交易 | 成功率下降、账本失败、摘要冲突突增、余额不足异常突增。 |
| 路由 | 缺平台账户、缺账本周期、缺快照回放、路由失败突增。 |
| 账本 | posting 不平衡、重复入账冲突、余额投影失败、分录摘要异常。 |
| 清结算 | 候选积压、批次失败、结算锁定失败、出款失败率升高。 |
| 对账 | 差错金额超阈值、超 SLA 差错、文件解析失败、重复流水异常。 |
| 归档 | 水位延迟、Manifest 差异、冷区校验失败、归档失败。 |
| 重放 | 无法续跑、差异数异常、影子对比不一致。 |
| 指标项承接 | 指标项缺口、来源口径待确认、异常反写风险。 |
| 安全 | 越权访问、无审批导出、高危操作失败、异常批量查询。 |
| 可解释输出 | 查询视图缺来源事实、错误原因缺下一步动作、告警缺负责人或 Runbook。 |

### 6.4 生产排障最小上下文

生产问题排查不能只看错误日志。任何资金写入、清结算确认、对账重跑、归档 apply 和投影重放失败时，至少要能从日志、trace、审计或任务记录中还原以下上下文。

| 上下文 | 必须能还原 |
| --- | --- |
| 业务入口 | 租户、业务场景、业务流水、请求摘要、操作者和来源系统。 |
| 资金路径 | 资金交易号、route snapshot、route code、主体、账目、币种和金额摘要。 |
| 账务结果 | posting plan 数、ledger transaction、entry 数、平衡校验结果和失败原因。 |
| 投影结果 | 余额投影 delta、交易投影任务、重放模式和差异摘要。 |
| 批处理范围 | 批次号、任务号、范围、checkpoint、watermark、Manifest 和差异报告。 |
| 安全审计 | 权限判断、审批号、凭证引用、脱敏/导出记录和拒绝原因。 |

### 6.5 面向使用者的可解释输出

可观测不仅服务研发排障，也要服务运营、财务、风控、客服和业务接入方理解资金状态。任何资金写入、清结算确认、对账差错、归档 apply 和投影重放失败，都应输出可解释摘要，而不是只输出内部异常。

| 输出对象 | 必须能解释 | 禁止 |
| --- | --- | --- |
| 用户账单 | 金额、方向、状态、冻结/授权/退款原因、失败是否可重试。 | 把授权占用写成最终消费，把冻结写成扣款。 |
| 商户账单 | 待清算、可结算、结算锁定、出款中、已出款、退款、争议和追偿。 | 把出款受理写成到账成功，把待清算写成可提现。 |
| 运营时间线 | 资金交易、route snapshot 摘要、账务结果、差错、审批、人工处理和下一步动作。 | 只显示技术错误码，不给失败阶段和处理建议。 |
| 财务对账视图 | 业务单、资金交易、账本分录、批次、外部流水、差错和核销引用。 | 只能看汇总金额，不能追溯单笔事实。 |
| 风控和安全审计 | 权限判定、审批、敏感数据脱敏、规则版本、外部证据和拒绝原因。 | 输出完整敏感凭证，或让未确认规则默认放行。 |
| SRE Runbook | 告警名称、触发条件、影响范围、定位入口、止血动作、恢复动作和恢复验收。 | 只有异常堆栈，没有业务键、任务范围、差异摘要或负责人。 |

### 6.6 告警到 Runbook 动作矩阵

告警不是生产可用性的装饰。每个告警都必须能触发明确动作，并能在恢复后验证资金事实、投影或批次状态已经回到一致。

| 告警域 | 触发条件 | 最小上下文 | Runbook 动作 | 恢复验收 |
| --- | --- | --- | --- | --- |
| 交易和账本 | 账本写入失败、posting 不平衡、幂等摘要冲突突增、余额投影失败。 | businessSn、idempotentKey、requestDigest、routeSnapshotId、ledgerTransactionSn。 | 暂停相关入口或灰度开关，确认是否有半截事实，按幂等键重试或进入人工差错。 | 交易状态、ledger entry、余额投影、审计和幂等结果一致。 |
| 权益快照 | 权益快照缺失、稳定摘要冲突、闭合角色非法、缺原快照 replay。 | benefitSnapshotId、stableDigest、componentSn、closureRole、originalTransactionSn。 | 阻断退款、清结算或对账消费，转人工处理，不按当前营销规则补算。 | 原快照或等价不可变存储可读；失败请求无 route/posting/entry 副作用。 |
| 清结算和对账 | 清算候选积压、重大差错、出款失败率升高、对账文件解析失败。 | batchSn、settlementSn、payoutSn、differenceSn、ruleVersion、amountSummary。 | 暂停批次确认或出款，复核差错等级，按放行矩阵或阻断矩阵处理。 | 批次状态、差错单、调账引用、重新对账结果和出款状态可追溯。 |
| 归档和重放 | Manifest 差异、无范围 apply、checkpoint 推进失败、dry-run/apply 差异异常。 | taskSn、range、mode、checkpoint、watermark、manifestSn、differenceReportSn。 | 暂停 apply，回到 dry-run 或只读校验，必要时回滚配置或停止任务。 | Manifest、watermark、checkpoint、差异报告和冷热查询结果一致。 |
| 敏感导出和高危操作 | 无审批导出、异常批量查询、越权访问、高危操作失败。 | operatorId、resourceType、resourceSn、approvalSn、scope、result。 | 立即阻断导出或操作，保留证据，通知安全/合规/负责人复核。 | 审批、脱敏、水印、下载审计和访问范围均可核验。 |

## 七、安全设计

### 7.1 权限模型

| 资源 | 动作 | 控制要求 |
| --- | --- | --- |
| 资金账户和余额 | 查询、导出 | 租户、主体、角色、数据范围校验。 |
| 资金交易 | 创建、查询、退款、批次授权调账 | 业务接入身份、幂等、操作权限和审计。 |
| 冻结单 | 冻结、解冻、查询 | 风控或运营权限，必要时审批。 |
| 余额控制 | 冻结、解冻、资金账户余额调整、信用账户额度调整、预算控制额度 / 窗口调整、查询 | 风控、运营或财务权限；资金和信用调整必须有来源、审批、凭证、原因和审计；预算控制调整只更新控制视图、规则快照和审计证据，不生成账本分录。 |
| 清算批次 | 创建、复核、确认、撤回 | 运营和财务分权，确认动作审计。 |
| 结算单和出款单 | 锁定、触发出款、确认回单 | 财务、出纳、风控分权，高危动作审批。 |
| 对账差错 | 分派、调账、核销 | 财务和运营权限；调账必须审批，并引用 BALANCE_ADJUST 或 DIRECT_TRANSACTION / ADJUSTMENT 事实。 |
| 归档重放 | 创建、执行、应用 | 研发、财务或数据权限，生产应用需审批。 |
| 指标和导出 | 查询、导出、发布 | 口径权限、敏感级别、审批、脱敏和水印。 |

### 7.3 敏感数据

1. 外部账户、支付工具、卡、VA、手机号、邮箱、证件、token、密钥、凭证必须脱敏或加密。
2. 日志、异常、指标、导出、告警不得输出敏感信息原文。
3. 敏感导出必须审批、脱敏、水印、下载审计和过期控制。
4. 测试数据不得使用真实客户、商户、账户、卡号、证件或生产流水。

## 八、金融系统红线

| 红线 | 系统控制 |
| --- | --- |
| 直接改余额 | 生产代码和后台禁止绕过交易、路由、账本修改余额投影。 |
| 外部账户入账 | Route 只允许内部可入账主体；外部账户和支付工具只能做引用。 |
| 分录不平衡 | LedgerPostingAssembler 和账本写入口必须双重校验。 |
| 历史分录可变 | DAL 和后台不提供修改或删除已过账分录入口。 |
| 缺快照逆向 | 退款、撤销、拒付、退费、解冻缺原快照必须失败或人工处理。 |
| 周期串账 | 查询和过账必须携带账本周期；非 LIFETIME 缺 periodId 失败。 |
| 授权拒绝入账 | 授权拒绝只记录拒绝事实，不生成账务路径。 |
| 冻结表达消费 | 冻结只做同主体可用性控制；扣划必须另建事实。 |
| 对账清算对象混用 | 对账批次、匹配结果、差错单、可清分明细、清分批次、清算候选、清算批次、结算单、出款单、追偿单分别建模。 |
| 对账差异直接改账 | 差异必须经过差错、审批、调账、重新对账和核销；重大差错不得带原因放行。 |
| 无范围重放 | 生产重放没有范围、原因、审批和差异报告必须失败。 |
| 指标反写事实 | 指标结果和报表处理不得修改资金事实。 |
| 绑定历史覆盖 | 支付工具、默认资金责任关系、平台账户角色或规则版本变更不得覆盖历史证据；逆向交易不得按当前关系重新解释。 |
| 敏感信息泄露 | 完整卡号、CVV、密钥、token secret、银行账户敏感号和证件原文不得进入普通快照、日志、报表、导出或测试数据。 |
| 资金性质混同 | 客户资金、商户待结算资金、平台自有资金、保证金、补贴资金和手续费收入必须按主体、账目和来源隔离；未确认资质、合同和资金归属前，不得把内部待结算口径实现成客户备付金能力。 |
| 持牌能力越界 | 清分、清算、结算、出款、跨境、外汇、卡组织、ACH、银行或通道规则未完成法务、合规、财务和合作机构确认前，只能作为待确认边界或 must-fail 用例，不能作为默认生产能力；ACH 指令、Debit 授权、文件批次、return code、NOC、reversal 和 Nacha/ODFI/RDFI 规则解释不得进入资金底座核心实现。 |

### 8.1 资金安全设计必须问的十个问题

设计评审、编码前 CR 和上线前检查都应逐条回答。回答不清楚时，结论只能是带条件通过或阻断。

1. 这笔资金事实的来源、业务流水、幂等键和请求摘要是否稳定。
2. 参与方是否已经解析为内部可记账主体，外部账户和支付工具是否只做引用。
3. 金额、币种、精度、汇率和累计剩余金额是否可校验。
4. route snapshot 是否足够支持退款、撤销、退费、拒付、解冻和重放。
5. posting plan 是否独立平衡，LedgerEntry 是否不可变且可追溯。
6. 余额投影、交易投影、余额日志和指标是否都保持只读派生边界。
7. 失败路径是否证明无 route、无 posting、无 entry 或无余额副作用。
8. 高危操作是否有权限、审批、原因、凭证、前后值和审计。
9. 批处理、归档、重放和出款是否有范围、幂等、告警和人工兜底。
10. 外部规则是否完成规则来源、版本或发布日期、生效日期、适用主体或适用范围、适用法域、核验日期、确认方和确认状态。

本矩阵用于把产品验收、DSL、系分和 TDD 的设计结论落到测试、观测、安全和生产证据。任一能力域进入编码前，必须先说明当前处于“可设计分析”“可 TDD 分析”“可工程落地复核”还是“可生产交付复核”，并补齐对应证据。

| 能力域 | 横切必须证明 | 可进入的工作 | 阻断或降级信号 |
